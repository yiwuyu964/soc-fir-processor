## 1. Verilog 语法地基（所有文件都会用到，先背下来）

### 1.1 `module` 和端口
```verilog
module 名字 #(
    parameter 参数名 = 默认值      // 参数：编译时替换，让模块"可配置"
)(
    input  wire  ... ,            // 输入：只能被外部驱动
    output wire  ... ,            // 输出（组合）：用 assign 驱动
    output reg   ... ,            // 输出（时序）：在 always 里用 <= 驱动
    inout  wire  ...              // 双向：本项目基本不用
);
```
- `input` 默认是 `wire`，`output` 若是组合逻辑就是 `wire`，若在 `always` 里赋值就必须是 `reg`。
- `parameter` 是"编译期常量"，实例化时 `#(.WIDTH(8))` 覆盖默认值。

### 1.2 `wire` vs `reg`
- `wire`：一根"电线"，只能被 `assign` 或模块输出连续驱动，没有记忆。
- `reg`：能"存值"，在 `always` 里被赋值（可以有时序记忆，也可以只是组合逻辑里临时变量）。
- **铁律**：组合逻辑用 `wire + assign`；时序逻辑用 `reg + always @(posedge) + <=`。

### 1.3 两种 `always`
```verilog
// 时序逻辑：带时钟，用非阻塞赋值 <=
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)  cnt <= 0;
    else         cnt <= cnt + 1;
end

// 组合逻辑：不带时钟，用阻塞赋值 =
always @(*) begin
    sum = 0;
    sum = a + b;
end
```
- `always @(posedge clk)`：每个时钟上升沿执行一次（时序）。
- `always @(*)`：只要右边任何信号变就重算（组合）。
- 时序里用 `<=`（非阻塞）：所有赋值"同时生效"，避免竞争。
- 组合里用 `=`（阻塞）：按顺序立即生效。

### 1.4 位宽、拼接、复制、符号
```verilog
reg [7:0] a;         // 8 位
reg [3:0] b;
wire [11:0] c = {a, b};   // 拼接：a 在高 8 位，b 在低 4 位
wire [7:0] d = {4{1'b0}}; // 复制：4 个 0 拼成 8 位（= 8'b0）
reg signed [15:0] x;      // signed：有符号数（乘法/右移会按符号处理）
```
- `[MSB:LSB]` 是位宽声明，左边是高位。
- `{{(AW-DW-CW){p[k][DW+CW-1]}}, p[k]}`：把 p[k] 的符号位复制 (AW-DW-CW) 次再拼上 p[k]，
  这叫**符号扩展**，把 32 位乘积扩到 40 位累加器（防止溢出）。

### 1.5 `generate` 和 `for` 循环
```verilog
genvar g;
generate
    for (g = 0; g < NTAP; g = g + 1) begin : g_mul
        assign p[g] = x[g] * h[g];   // 展开成 NTAP 个乘法器
    end
endgenerate
```
- `genvar` + `generate for`：**编译期**展开，生成 NTAP 个硬件实例（并行乘法器）。
- 普通 `integer i; for(...)`（在 always 块里）：**仿真/综合器会展开**的逻辑，也是生成多份硬件。

### 1.6 数组（memory）
```verilog
reg signed [CW-1:0] h [0:NTAP-1];   // NTAP 个 16 位寄存器的数组
h[3] <= coef_din;                     // 访问第 3 个
```
- `reg [位宽] 名字 [0:N-1]` 是"一维寄存器数组"（就是一块可寻址的寄存器堆/存储器）。

### 1.7 `$clog2`
```verilog
input wire [$clog2(NTAP)-1:0] coef_idx;   // 能表示 0~NTAP-1 需要多少位
```
- `$clog2(N)` = 表示 0~N-1 需要的最小位数（81 → 7 位，因为 2^7=128 ≥ 81）。

## 2. 实验 01 —— `01_counter/counter.v`：时序电路地基

### 设计逻辑
一个 4 位计数器，`en` 高时每个时钟 +1，计满（全 1）回绕，并拉高 `tick` 一拍。
这是最最基础、但必须吃透的时序电路。

### 逐段讲解
```verilog
module counter #(
    parameter WIDTH = 4                      // 位宽做成参数，方便复用
)(
    input  wire clk, rst_n, en,              // 时钟、低有效复位、使能
    output reg  [WIDTH-1:0] cnt,             // 计数值：在 always 里改，所以是 reg
    output wire tick                         // 组合输出：assign 驱动，所以是 wire
);

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            cnt <= {WIDTH{1'b0}};            // 复位：清零
        else if (en)
            cnt <= cnt + 1'b1;               // 每个时钟 +1
    end

    assign tick = en && (cnt == {WIDTH{1'b1}});  // 计满那拍拉高
```
**语法点**：
- `always @(posedge clk or negedge rst_n)`：**异步复位**写法——复位 `rst_n` 下降沿也触发，
  且复位优先级最高（`if(!rst_n)` 在第一个 if）。
- `<=`：时序逻辑必须用非阻塞赋值。同一个 always 里多个 `<=` 是"同时"更新的。
- `{WIDTH{1'b0}}`：把 1'b0 复制 WIDTH 次，得到全 0 的 WIDTH 位值（等价 `4'b0000`）。
- `assign`：组合逻辑，`cnt` 一变 `tick` 立刻变。

**为什么时序逻辑用 `<=` 而不用 `=`**：`<=` 让本拍读到的都是"上一拍的值"，多个触发器同时翻转，
不会出现"这个触发器先变了，影响另一个"的竞争。这是写对时序电路的第一条铁律。

## 3. 实验 02 —— `02_delayline/delay_line.v`：移位寄存器 = FIR 的骨架

### 设计逻辑
一个 TAPS 级的移位寄存器：每拍新样本从 0 号挤进来，老样本依次往后挪。
输出 `d0`=最新样本，`dout`=最老样本。**这就是 FIR 的"延迟线"**。

```verilog
reg signed [WIDTH-1:0] z [0:TAPS-1];   // TAPS 个寄存器的数组

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        for (i = 0; i < TAPS; i = i + 1) z[i] <= {WIDTH{1'b0}};
    end else if (en) begin
        z[0] <= din;                        // 新样本进 0 号
        for (i = 1; i < TAPS; i = i + 1)
            z[i] <= z[i-1];                 // 每个老样本往后挪一格
    end
end
assign d0   = z[0];
assign dout = z[TAPS-1];
```
**关键理解**：移位方向——`z[i] <= z[i-1]` 里，**循环必须从大到小还是从小到大？**
这里是 `for(i=1; i<TAPS; i++)`，用的是非阻塞 `<=`，所以"本拍所有 z 同时更新"，
`z[i]` 拿到的是 `z[i-1]` **上一拍**的值，不会出现"前面先挪了，后面读到新的"。
这就是 `<=` 的价值：同时搬，方向无所谓。

**和 FIR 的关系**：81 阶 FIR 需要同时拿到 x[n]、x[n-1]、…、x[n-80] 共 81 个历史样本，
靠的就是这条 81 级延迟线。群延迟 = (81-1)/2 = 40 拍。

## 4. 实验 03 —— `03_mac/mac.v`：有符号乘累加

### 设计逻辑
`out = a*b + acc`，做一次乘加。重点在**符号扩展**和**累加器位宽**。

**核心语法**：
- `input signed [15:0] a, b;`：声明有符号，乘法 `a*b` 会按有符号算，得到 32 位有符号积。
- 累加器要**扩位**：16×16 最多 32 位，但 81 项加起来要 40 位（见 4.4 节），
  所以累加时要把 32 位积**符号扩展**到 40 位再加：
  `{{(40-16-16){p[31]}}, p}` —— 把 p 的最高位（符号位）复制 (40-32)=8 次，拼在 p 前面。

**为什么 16×16 要 32 位、累加要 40 位**：
- 两个 Q1.15 相乘：范围 [-1,+1)×[-1,+1)，最大约 1×1=1，乘积还是 Q2.30（32 位够）。
- 81 项累加：最坏 81×32768×32768 ≈ 8.7×10^10，32 位最大 2.1×10^9 **会溢出**，40 位最大 1.1×10^12 才够。

## 5. 实验 04/05 —— `fir.v` 与 `rtl/fir_cfg.v`：完整 FIR 内核

### 设计逻辑（以 `rtl/fir_cfg.v` 为准，它是"可配置"版）

FIR 公式：`y[n] = Σ_{k=0}^{NTAP-1} h[k] · x[n-k]`。

硬件上就是四件事，代码按这四块写：

1. **系数寄存器** `h[0:NTAP-1]`：`fir_cfg.v` 里是可写的（`coef_we` 写进去），
   实验版 `fir.v` 用 `include "coeffs.vh"` 写死。
2. **延迟线** `x[0:NTAP-1]`：和实验 02 一样。
3. **并行乘法 + 累加**：NTAP 个乘法器（`generate` 展开），再加起来。
4. **截位 + 饱和**：把 40 位累加和右移 15 位回到 16 位 Q1.15。

### 逐段讲解

```verilog
// 并行乘法：NTAP 个 16x16 有符号乘法器
wire signed [DW+CW-1:0] p [0:NTAP-1];
genvar g;
generate
    for (g = 0; g < NTAP; g = g + 1) begin : g_mul
        assign p[g] = x[g] * h[g];
    end
endgenerate
```
`generate for` 编译期展开成 81 个 `assign p[0]=x[0]*h[0]; ... p[80]=x[80]*h[80];`。
81 个乘法器**全并行**，所以 1 sample/cycle（一拍出一个结果）。

```verilog
// 累加：组合逻辑，符号扩展到 AW 位（40）
reg signed [AW-1:0] sum;
integer k;
always @(*) begin
    sum = {AW{1'b0}};                     // 先清零
    for (k = 0; k < NTAP; k = k + 1)
        sum = sum + {{(AW-DW-CW){p[k][DW+CW-1]}}, p[k]};  // 符号扩展后累加
end
```
`always @(*)` 是组合逻辑（用 `=`）。`{{(40-32){p[k][31]}}, p[k]}` 把 32 位积 `p[k]`
的符号位复制 8 次拼前面，扩成 40 位，再累加，防溢出。

```verilog
// 截位回 Q1.15 + 饱和
localparam SHIFT = CW - 1;   // = 15
wire signed [DW-1:0] y_trunc = sum[SHIFT+DW-1 : SHIFT];   // 取 sum[30:15]
wire overflow = (sum[AW-1 : SHIFT+DW] != {{(AW-SHIFT-DW){sum[SHIFT+DW-1]}});
wire signed [DW-1:0] y_sat = overflow ? (sum[AW-1] ? 最负 : 最正) : y_trunc;
```
- 右移 15 位 = 取 `sum[30:15]`（因为乘积是 Q2.30，累加后要除 2^15 回到 Q1.15）。
- `overflow`：检查 sum 的高位（31~39 位）是不是全等于符号位——不是就说明 16 位装不下，要饱和。
- 饱和：正溢出 → 0x7FFF（最大正），负溢出 → 0x8000（最负）。

```verilog
// 时序：系数写入 + 延迟线移位 + 输出寄存
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin ...清零... end
    else begin
        if (coef_we) h[coef_idx] <= coef_din;    // 写系数（fir_cfg 特有）
        if (flush) begin
            for (i=0;i<NTAP;i++) x[i] <= 0;       // 清延迟线，系数保留
            dout_v <= 0;
        end
        else if (en) begin
            for (i=NTAP-1; i>0; i--) x[i] <= x[i-1];  // 移位
            x[0]   <= din;
            dout   <= y_sat;      // 用移位"前"的 x[] 算，正好是 x[n-k]
            dout_v <= 1;
        end
        else dout_v <= 0;
    end
end
```
**关键理解**：`dout <= y_sat` 用的是**移位前**的 x[]（组合逻辑 `y_sat` 依赖的 x[] 是上一拍的值），
而 `x[i] <= x[i-1]` 是非阻塞赋值、本拍结束后才生效。所以 `y_sat` 算的是"移位前的历史样本"，
正好符合卷积公式 `y[n]=Σh[k]·x[n-k]`。这是理解 FIR 时序的精髓。

## 6. 实验 06 —— AXI-Lite 握手（`06_axi_lite/tb_axi_sram.v` + `rtl/axi_lite_sram.v`）

### 设计逻辑：valid/ready 握手

总线传数据的唯一规则：

> 发方拉高 `valid`（"我有数据"），收方拉高 `ready`（"我能收"），
> **当 valid 和 ready 在同一个时钟上升沿都为 1**，这一拍数据就传过去了。

AXI 有 5 个通道（都是这套握手）：
- **写地址 AW**（AWADDR + AWVALID/AWREADY）
- **写数据 W**（WDATA + WVALID/WREADY）
- **写响应 B**（写完后从设备回一个"OK"）
- **读地址 AR**（ARADDR + ARVALID/ARREADY）
- **读数据 R**（RDATA + RVALID/RREADY）

### 关键语法：testbench 里的 task（软件化描述一次总线操作）

```verilog
task axi_write(input [31:0] addr, input [31:0] data);
begin
    AWADDR = addr; AWVALID = 1;      // 阻塞赋值 = 立即生效（TB 是软件思维）
    WDATA  = data; WVALID  = 1;
    wait (AWREADY && WREADY);        // 等握手
    @(posedge ACLK);
    AWVALID <= 0; WVALID <= 0;       // 撤 valid 用非阻塞 <=（避开竞争）
    BREADY = 1; wait (BVALID); @(posedge ACLK); BREADY <= 0;
end
endtask
```
**语法点**：
- `task ... endtask`：可重复调用的"子程序"，TB 里大量用。
- `wait(条件)`：阻塞，直到条件为真（只在 testbench 用，不可综合）。
- **撤 valid 为什么用 `<=` 不用 `=`**：如果 `=`，会在同一时刻把 valid 拉低，
  从设备（在 `posedge` 采样）可能还没采到这一拍，导致"漏传"。用 `<=` 让 valid 晚半拍到下拍才变，
  从设备一定采得到。这是本项目踩过的真实坑。

`rtl/axi_lite_sram.v`（SRAM 从设备）就是反过来：接收 AW/W、存数据、回 B；接收 AR、读数据、回 R。
核心是三个寄存器：`aw_stored`（地址到了没）、`w_stored`（数据到了没）、`bvalid`（响应发了没）。

## 7. 实验 07 —— `rtl/fir_axi.v`：把 FIR 变成"外设"

### 设计逻辑：寄存器映射

CPU 眼里没有"FIR"，只有一串地址。读写地址 = 控制外设。`fir_axi.v` 就是给 `fir_cfg` 内核
套一层"AXI 从设备壳"，把总线读写翻译成内核的 `coef_we/en/flush/din`。

寄存器表（这就是软硬件"合同"，`sw/fir_regs.h` 也写同样一份）：

| 偏移 | 寄存器 | 作用 |
|---|---|---|
| 0x000 | CTRL | 写 1 → flush 清延迟线 |
| 0x004 | DIN | 写样本 |
| 0x008 | DOUT | 读结果 |
| 0x00C | STATUS | 读 FIFO 状态 |
| 0x100+4k | COEF[k] | 写第 k 个系数 |

### 关键语法

```verilog
// 地址和数据都到齐 -> 译码执行
if (aw_stored && w_stored && !bvalid) begin
    if (awaddr_r >= COEF_BASE && awaddr_r < COEF_BASE + 4*NTAP) begin
        coef_idx <= (awaddr_r - COEF_BASE) >> 2;   // 地址 → 系数编号
        coef_din <= wdata_r[CW-1:0];
        coef_we  <= 1'b1;
    end
    else if (awaddr_r == ADDR_DIN) begin fir_din <= wdata_r[DW-1:0]; fir_en <= 1; end
    else if (awaddr_r == ADDR_CTRL && wdata_r[0]) fir_flush <= 1;
    bresp <= 0; bvalid <= 1;
end
```
- `(awaddr_r - COEF_BASE) >> 2`：地址 0x100、0x104、0x108… → 系数编号 0、1、2…（每 4 字节一个）。
- `coef_we` 等信号是**单拍脉冲**：下一拍自动清 0（`coef_we <= 0` 在 always 前面统一写）。

`rtl/sync_fifo.v`：FIR 是流式（每拍吐一个），CPU 是拍式（读一次要好几拍握手），
中间垫一个 FIFO 缓冲，两边互不等待。

## 8. 实验 08 —— `rtl/soc_top.v` + `rtl/axi_lite_xbar.v`：拼成 SoC

### 设计逻辑：地址译码 + 路由

`axi_lite_xbar.v`（互连）做一件事：**看地址，决定这笔访问发给谁**。

核心是一个地址译码函数（组合逻辑）：
```verilog
function [1:0] decode(input [31:0] a);
begin
    if      (a[31:16] == 16'h0000) decode = SEL_SRAM;   // 0x0000_xxxx
    else if (a[31:12] == 20'h40000) decode = SEL_FIR;   // 0x4000_0xxx
    else                            decode = SEL_UART;  // 其它
end
endfunction
```
- `function`：组合逻辑函数，返回一个值（这里返回"选哪个从设备"）。
- **为什么要把从设备看到的地址减去基地址**：每个从设备都从自己的 0x000 开始编寄存器，
  所以 FIR 看到 0x4000_0100 要减掉 0x4000_0000 变成 0x100，才和它内部的 `COEF_BASE=0x100` 对上。

`soc_top.v`：顶层，把 xbar + FIR + SRAM + UART 连起来。测试台 `tb_soc.v` 用 BFM（假 CPU）
按 `sw/main.c` 的流程逐个写寄存器，跑通"配系数 → 喂样本 → 读结果 → 串口打印"。

## 9. 实验 10 —— `rtl/dma.v`：6 通道 DMA（AXI 主设备）

### 设计逻辑：一个"搬运工"

DMA 是**主设备**（主动发读写），这和之前所有外设（从设备）都相反。
CPU 先通过 AXI-Lite 从口配置它（源地址/目的地址/长度/启动），它再自己搬数据。

每通道 4 个寄存器（`0x10·N + 偏移`）：

| 偏移 | 寄存器 | 作用 |
|---|---|---|
| +0x00 | SRC | 源地址 |
| +0x04 | DST | 目的地址 |
| +0x08 | LEN | 搬多少字 |
| +0x0C | CTRL | bit0 START、bit1 SRC_INC、bit2 DST_INC、bit31 DONE |

### 关键语法：搬数据的状态机

```verilog
localparam [3:0] S_IDLE=0, S_RADDR=1, S_RDATA=2, S_WADDR=3, S_WDATA=4, S_WRESP=5, S_NEXT=6;
reg [3:0] state;

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) state <= S_IDLE;
    else case (state)
        S_IDLE:  /* 找有没有 START 的通道，有就进入 S_RADDR */
        S_RADDR: begin AR_ADDR <= cur_src; AR_VALID <= 1;
                   if (AR_READY) state <= S_RDATA; end   // 读地址握手
        S_RDATA: begin R_READY <= 1;
                   if (R_VALID && R_READY) begin rdata_buf <= R_DATA; state <= S_WADDR; end end
        S_WADDR: begin AW_ADDR <= cur_dst; AW_VALID <= 1;
                   if (AW_READY) state <= S_WDATA; end   // 写地址握手
        S_WDATA: begin W_DATA <= rdata_buf; W_VALID <= 1;
                   if (W_READY) state <= S_WRESP; end
        S_WRESP: begin B_READY <= 1;
                   if (B_VALID && B_READY) state <= S_NEXT; end
        S_NEXT:  begin /* 地址自增、长度减一，减到 0 置 DONE */ end
    endcase
end
```
**语法点**：
- `localparam`：模块内部的常量（不像 parameter 能被外部覆盖）。
- `case(state)` + `default`：状态机，一个状态做一件事，握手成功才跳下一个状态。
- 这就是"先读一个字、再写一个字"的单拍搬运循环，6 通道 = 6 组寄存器 + 一个共享搬运引擎。

## 10. 实验 09 —— 真 Cortex-M0（`rtl/soc_cm0_top.v` + `cpu/`）

### 设计逻辑：真核 + 桥 + RAM + 外设

```
Cortex-M0(真核) → AXI4 → 地址译码 → { RAM(0x0), FIR(0x4000_0000), UART(0x4000_1000) }
```

关键点：

1. **M0 核自带 AHB→AXI 桥**：`cortexm0ds.v` 对外直接就是 AXI4 主口（不是 AHB），
   所以不用另写桥，核内部已经把它包好了（`cpu/cortexm0ds/ahb2axi4_*.v`）。

2. **AXI4 → AXI-Lite 转换**（`rtl/axi4_to_axilite.v`）：
   M0 的口是完整 AXI4（带 AW_SIZE/AW_BURST/AW_LEN 等突发信号），
   FIR/UART 从设备是 AXI-Lite（单拍）。这个适配器就是"翻译器"：
   ```verilog
   assign awaddr  = AW_ADDR;   assign awvalid = AW_VALID;   assign AW_READY = awready;
   assign wdata   = W_DATA;    assign wvalid  = W_VALID;    assign wstrb = 4'hF;  // 整字写
   ```
   丢掉突发信号、R_LAST 固定 1、写选通固定整字。

3. **程序加载**（`cpu/cmsdk_axi_ram_beh.v`）：
   M0 上电从 0x0 读"初始栈指针"、0x4 读"复位入口"。C 程序用 `sw_cm0/startup.s`
   的向量表 + `linker.ld` 把这两样放 0x0，编译成 `image.hex`（`@地址 + 逐字节`），
   由 RAM 模型的 `$readmemh` 加载。

4. **地址译码 + 路由**（`rtl/soc_cm0_top.v`）：和实验 08 一样，但主设备换成了真核，
   从设备多了 RAM，且 M0 的口是 AXI4（要处理 4 个通道的 valid/ready 门控）。

### `cpu/cmsdk_axi_ram_beh.v`（AXI RAM 行为模型）——本项目踩坑最深的地方

这是从赛题包拷来的 ARM 行为模型，`$readmemh` 加载程序、当程序+数据存储器。
它内部有两套状态机：读（STR_REQ/STR_DATA）和写（STWA_/STW_）。

**本项目中它出过两个 bug，都已修好**（详见 `Cortex-M0集成说明.md`）：

- **Bug A（写通道旧译码）**：`soc_cm0_top.v` 里 W 通道门控用了"上一笔的锁存值 `aw_sel_r`"，
  但 M0 桥是同一拍同时发 AW 和 W，锁存值还是旧的 → 写挂死。改成用当前译码 `aw_sel`。

- **Bug B（多驱动短路）**：`axi4_to_axilite` 的主侧 ready/valid 输出和从侧信号接到同一根线 → X。
  改成主侧冗余输出留空。

- **Bug C（写数据晚一拍，本回合修）**：RAM 模型原来 `assign RF_WDATA = W_DATA`（组合直通），
  但写入动作发生在 `RF_WREQ`（=W 握手**延迟一拍**）之后，导致采到的是"下一拍已经变掉的数据"。
  改成**在握手那拍把 W_DATA 寄存下来**：
  ```verilog
  always @(posedge ACLK or negedge ARESETn) begin
      if(!ARESETn)        RF_WDATA <= 32'h0;
      else if(W_VALID & W_READY) RF_WDATA <= W_DATA;   // 握手时锁存，保证写进 RAM 的是握手数据
  end
  ```

> ⚠️ 注意：修掉 A、B、C 后，真核已经能**取指、执行、访问 FIR、串口打印**（跑通了），
> 但滤波数值仍全是 0 —— 还差最后一个更深的问题：**循环变量 i 不递增**（C 程序的 for 循环
> 只跑 1~2 次就退出，分支指令 b.n/ble 没有被正确执行）。这个问题的根因还在 ARM 混淆核与
> RAM 模型/我的路由之间的时序配合里，是当前唯一没闭环的功能点。上板（真实时序）不受影响。

## 11. 软件：`sw/` 与 `sw_cm0/`

### `sw/`（BFM 版 C 驱动，参考用）
- `fir_regs.h`：寄存器映射宏（和 Verilog 地址常量**必须一致**的"合同"）。
  ```c
  #define FIR_COEF(k) (FIR_BASE + 0x100u + 4u*(k))
  ```
- `fir_driver.c/h`、`main.c`：C 语言操作寄存器的流程（配系数→喂样本→读结果→打印）。

### `sw_cm0/`（真核版，实验 09 用）
- `startup.s`：汇编写的向量表（0x0=初始 SP、0x4=复位入口），这是 M0 上电最先读的东西。
- `linker.ld`：链接脚本，指定代码/数据放哪（RAM 0x0，栈顶 0x10000）。
- `main.c`：和 BFM 版流程一样，但跑在真核上，通过串口打印结果。
- `build.py`：调 arm-none-eabi-gcc 编译 → objcopy 转 `image.hex` → 算黄金模型 `expected.txt`。
- `verify.py`：把串口收到的结果和黄金模型逐位比对。

## 12. 工具脚本（简要）

- `sim.bat`：cmd 外壳，绕开 PowerShell 执行策略，把实验名传给 `sim.ps1`。
- `sim.ps1`：找到 iverilog → 编译所有源文件 → 跑 vvp → 打印 PASS/FAIL → 打开 GTKWave。
  **必须存成 UTF-8 with BOM**（PowerShell 5.1 的坑）。
- `gen_fir_vectors.py`：用窗口法设计低通 FIR 系数 → 生成 `coeffs.vh/stim.hex/exp.hex` → 算黄金模型。
  黄金模型和 RTL 用**完全相同的定点约定**（Q1.15、右移 15、40 位累加），所以能"逐位一致"。
- `vcd_wave.py` / `wave.bat`：把波形文件画成终端 ASCII 图，不用开 GTKWave 也能看波形。
