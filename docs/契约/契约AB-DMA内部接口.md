## 一、为什么单独一份文档

阶段 3 的分工文档只写了端口清单，没写语义。语义不定清楚，A 和 B 会各按各的理解写，最后拼起来发现十几种对不上的情况——最典型的是 `LEN=0`，一个人理解成"传 0 个字"，另一个人理解成"传 1 个字"，两种都能自圆其说，跑起来才发现差一拍。

所以本文把每个信号的含义、取值、边界情况和时序全部写死。

## 二、契约 A：`dma_regs` 到 `dma` 顶层的配置总线

### 2.1 端口

```verilog
// dma_regs 输出（6 通道 × 32 bit 展平，第 ch 通道占 [ch*32 +: 32]）
output wire [6*32-1:0] cfg_src;     // 源地址（字节地址，32 bit）
output wire [6*32-1:0] cfg_dst;     // 目的地址（字节地址，32 bit）
output wire [6*32-1:0] cfg_len;     // 传输字数（32bit 字个数）
output wire [6*32-1:0] cfg_ctrl;    // 控制，位定义见 2.2

// dma_regs 输入（状态回读）
input  wire [6*32-1:0] st_status;   // 每通道状态，位定义见 4.1
```

### 2.2 `cfg_ctrl[ch]` 的位定义

| 位 | 名称 | 方向 | 含义 |
|---|---|---|---|
| `[0]` | START | 输出 | **一拍脉冲**，不是电平。`dma_regs` 在 CPU 写 `CTRL[0]=1` 的下一拍产生一个时钟周期的高电平，其余时候恒 0 |
| `[1]` | SRC_INC | 输出 | 1 = 源地址每传一个字加 4；0 = 源地址保持不变 |
| `[2]` | DST_INC | 输出 | 1 = 目的地址每传一个字加 4；0 = 目的地址保持不变 |
| `[31:3]` | 保留 | 输出 | 恒 0 |

### 2.3 寄存器映射

按 `../任务3-地址映射与中断分配.md` 4.2 节，每通道 16 字节，基址 `0x4000_1000`：

| 偏移 | 名称 | 访问 | 说明 |
|---|---|---|---|
| `0x00 + 0x10·N` | SRC | W | 源地址（字节） |
| `0x04 + 0x10·N` | DST | W | 目的地址（字节） |
| `0x08 + 0x10·N` | LEN | W | 传输字数（32bit 字个数） |
| `0x0C + 0x10·N` | CTRL | W/R | 见 2.4 |

六通道共占 `0x00` 到 `0x5F`。

### 2.4 CTRL 的写读语义

写操作：

| 位 | 名称 | 写 1 的效果 |
|---|---|---|
| `[0]` | START | 启动本通道。写 1 后自动清 0，读回恒 0 |
| `[1]` | SRC_INC | 置位 |
| `[2]` | DST_INC | 置位 |
| 其余 | 保留 | 忽略，读回恒 0 |

读操作把引擎状态映射到高位，这是解决"CTRL 既要能写又要能读状态"这个冲突的关键：

| 位 | 名称 | 来源 | 说明 |
|---|---|---|---|
| `[0]` | START | — | 恒 0（自清） |
| `[1]` | SRC_INC | 寄存器 | |
| `[2]` | DST_INC | 寄存器 | |
| `[29]` | ERR | `st_status[ch][2]` | 上一次传输出错 |
| `[30]` | BUSY | `st_status[ch][0]` | 正在传输 |
| `[31]` | DONE | `st_status[ch][1]` | 上一次传输完成 |
| `[28:3]` | 保留 | — | 读回 0 |

这样既满足了任务三 4.2 原有的「bit31 DONE」约定（没有破坏既有定义），又把原先缺失的 BUSY 和 ERR 补在了 `[30]` 和 `[29]`。任务三那份文档已经同步补进去了。

### 2.5 边界情况

这一节的每一条原来都没定，全是靠踩坑才明确下来的。

| # | 情况 | 规定 |
|---|---|---|
| A-1 | `LEN = 0` | 传输 0 个字。不产生任何 AXI 事务，`start` 后 1~2 拍内给出 `done`。**注意这和 AXI 的 `AWLEN=0` 不是一回事**——后者表示 1 拍。要传 1 个字就写 `LEN=1` |
| A-2 | `LEN` 上限 | 无硬上限。引擎负责按 4KB 边界拆成多个突发（见 3.5）。CPU 写 1M 是合法的 |
| A-3 | 传输途中 CPU 改 SRC/DST/LEN | 不影响本次传输。引擎在 `start` 那一拍已锁存配置（见 3.6），新值在下一次 `start` 生效 |
| A-4 | BUSY 期间再写 `START=1` | 忽略，丢弃这次启动请求，不排队也不重传。引擎继续跑原来的传输 |
| A-5 | 未启动就读 CTRL | `DONE=BUSY=ERR=0`，复位后的初值 |
| A-6 | 复位 | 所有寄存器清零，`cfg_*` 输出全 0，不产生 `START` 脉冲 |

## 三、契约 B：`dma_engine` 的端口

### 3.1 端口清单

```verilog
module dma_engine #(
    parameter ADDR_W = 32,
    parameter DATA_W = 32,
    parameter ID_W   = 4,
    parameter LEN_W  = 8,
    parameter CH     = 0            // 通道号，用于生成 AXI ID（契约C）
)(
    input  wire                clk,
    input  wire                rst_n,

    // 配置（来自 dma_regs，顶层解包后送入）
    input  wire [ADDR_W-1:0]   cfg_src,
    input  wire [ADDR_W-1:0]   cfg_dst,
    input  wire [31:0]         cfg_len,       // 传输字数
    input  wire                cfg_src_inc,   // 0 = 源地址保持（UART/FIR 固定地址）
    input  wire                cfg_dst_inc,
    input  wire                start,         // 一拍脉冲，顶层直接接，不做边沿检测

    // 状态
    output wire                busy,
    output reg                 done,          // 完成脉冲（一拍）
    output reg                 err,           // 错误脉冲（一拍）
    output wire [31:0]         status,        // 见 4.1

    // AXI4 主口（标准信号，见 ../阶段划分/阶段3-三人分工.md）
);
```

### 3.2 递增标志为什么是独立端口

`cfg_ctrl[ch][1]` 和 `[2]` 是源头，也就是 CPU 写的寄存器。顶层负责解包：把 `cfg_ctrl[ch][1]` 接到引擎的 `cfg_src_inc`，`[2]` 接到 `cfg_dst_inc`；引擎只认这两个独立端口，自己不去看 `cfg_ctrl`。

这么切是为了让引擎端口保持"一个信号管一件事"，单元测试好写；打包解包本来就是顶层的活。

### 3.3 `start` 的时序

`start` 是一拍脉冲，直接来自契约 A 的 `cfg_ctrl[ch][0]`。引擎在它有效的那一拍锁存配置并开始工作。`busy=1` 时到来的 `start` 被忽略。`start` 与复位同时有效时复位优先。

### 3.4 `busy` / `done` / `err` 的时序

| 信号 | 起止 |
|---|---|
| `busy` | `start` 被接受的下一拍拉高；最后一个写响应到达或错误发生后拉低。与 `status[0]` 完全一致 |
| `done` | 传输成功完成时拉高一拍 |
| `err` | 发生错误时拉高一拍 |
| `status[1]`(DONE) / `status[2]`(ERR) | 保持，直到下一次 `start` 被接受时清除 |

`done` 做成脉冲而 `status[DONE]` 做成保持，是因为两者用途不同：脉冲给中断逻辑用，避免重复触发；保持给寄存器读回用，CPU 什么时候来读都能看到结果。

### 3.5 引擎发出的 AXI 事务规格

| 信号 | 取值 | 说明 |
|---|---|---|
| `m_awsize` / `m_arsize` | `3'b010` | 每次传输 4 字节，一个字 |
| `m_awburst` / `m_arburst` | `2'b01`（INCR）或 `2'b00`（FIXED） | 地址递增用 INCR；地址固定（FIR 的 DIN/DOUT、UART 固定地址）用 FIXED |
| `m_wstrb` | `4'hF` | 整字写，永远四位全 1 |
| `m_awlen` / `m_arlen` | `0 ~ 255` | 单个突发 1 到 256 拍 |
| `m_awid` / `m_arid` | `{CH[2:0], 1'b1}` | 契约 C，见独立文档 |

突发类型跟着 `cfg_src_inc`/`cfg_dst_inc` 走，这一点是"三种传输场景"（存储器↔FIR、存储器↔存储器、UART↔存储器）能成立的前提：地址固定时用 FIXED，地址递增时用 INCR，一套逻辑覆盖全部场景。

突发拆分由引擎负责，顶层不管，规则四条：

单个突发不超过 256 拍。不跨 4KB 边界，拆点时取"距离下一个 4KB 边界还剩几个字"和"还剩几个字"的较小值。最后一个突发可以短于 256 拍。FIXED 模式下地址不动，没有 4KB 限制，只受 256 拍上限约束。

举个具体例子：从 `0x4000_0FF0` 传 100 个字，第一个突发只能 4 拍（到 `0x4000_0FFF` 边界），之后按 256 拍拆，最后一段是余数。

### 3.6 配置锁存

引擎必须在 `start` 那一拍把 `cfg_src`/`cfg_dst`/`cfg_len`/`cfg_src_inc`/`cfg_dst_inc` 锁存到内部寄存器，之后整个传输只用锁存值。

这样 `busy` 期间 CPU 改寄存器不会影响正在跑的传输。

### 3.7 错误处理

错误只有两种来源：B 通道握手时收到 `BRESP` 为 `SLVERR` 或 `DECERR`；R 通道握手时收到 `RRESP` 为 `SLVERR` 或 `DECERR`。

发生错误后引擎按这个顺序做五件事：停止发起新的 AXI 事务；把已经发出的读写事务收尾（不能半路扔下，否则协议违规）；拉 `err` 一拍；`status[2]` 置 1，`busy` 拉低；已经搬过去的数据不回滚——DMA 不做原子性保证。

### 3.8 AXI 握手行为

`m_awvalid`/`m_wvalid`/`m_arvalid` 一旦拉高必须保持到握手完成（AXI 规范 A3.2.1）。`m_bready`/`m_rready` 能收就收，不做无谓背压。VALID 不许等 READY，这条组合依赖由 `TB/axi_protocol_checker.v` 做代码审查抓。顶层仲裁未授权时，引擎保持 VALID 不变，不许撤销，等授权。

## 四、状态与中断

### 4.1 `st_status[ch]` 与 `status` 的位定义

两个信号位定义完全相同：

| 位 | 名称 | 含义 |
|---|---|---|
| `[0]` | BUSY | 正在传输 |
| `[1]` | DONE | 上一次传输完成，保持到下次 `start` |
| `[2]` | ERR | 上一次传输出错，保持到下次 `start` |
| `[31:3]` | 保留 | 恒 0 |

数据流是：引擎输出 `status` → 顶层打包成 `st_status` → `dma_regs` 映射进 `CTRL[31:29]`。

### 4.2 中断语义

| 信号 | 类型 | 说明 |
|---|---|---|
| `irq_done[5:0]` | 电平 | 第 ch 位等于该通道的 `st_status[ch][1]`（DONE） |
| `irq_err` | 电平 | 6 个通道 `st_status[ch][2]` 的按位或 |

没有单独的清除位：下次对该通道写 `START` 时 DONE/ERR 被清，中断线随之拉低。

这里有个使用上的限制要写进驱动的说明：`irq_err` 只有 1 位（`../任务4-模块接口信号清单.md` 1.6 节），光看中断线分不出是哪个通道出的错。CPU 收到 `irq_err` 之后要逐个读六个通道的 `CTRL[29]` 才能定位。

## 五、链式传输的预留

决赛要加"描述符链表"时不想返工，所以现在就把接口位置留出来。`cfg_ctrl[ch]` 的高位本阶段恒 0，`dma_regs` 也不实现：

| 位 | 名称 | 决赛含义 |
|---|---|---|
| `[8]` | CHAIN_EN | 1 = 本通道完成后自动触发下一通道 |
| `[11:9]` | CHAIN_NEXT | 下一通道号（0~5） |

引擎和顶层预留这三个端口，本阶段恒 0、不连线：

```verilog
input  wire        chain_en,     // 1 = 完成后触发下一通道
input  wire [2:0]  chain_next,   // 下一通道号
output wire        chain_trig    // 完成时输出一拍脉冲，给下一通道当 start
```

本阶段的要求只有三条：端口留出来、注释写清楚、连 0。不实现逻辑。
