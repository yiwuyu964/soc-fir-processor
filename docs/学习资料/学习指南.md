# 学习指南：从零到 81 阶 FIR 数字滤波器的 SoC 处理器设计

> 面向：基本没接触过数字电路的大二学生。
> 目标：通过读懂、跑通、改动手里的这个项目，学会"高阶 FIR + SoC"是怎么做出来的。
> 前提：你不需要一次看懂全部，只要按本文的顺序"跑一个、懂一个、再下一个"。

## 0. 先给你吃一颗定心丸

赛题（飞腾）本质上是让你做一个东西：

> 一个 CPU（Cortex-M0）+ 一条总线（AXI）+ 一个 81 阶 FIR 滤波器 + 一个 UART + 一个 DMA，
> 让 CPU 用 C 语言程序配置滤波器、搬数据、读结果。

听起来很吓人，但它可以拆成一小块一小块，每一小块都简单到"大二能懂"。
本项目的做法就是：**先把 FIR 做对（已经在实验 01~05 完成了），再学会总线（实验 06），
再把 FIR 挂到总线上（实验 07），最后拼成完整 SoC（实验 08）**。

你现在手里已经有一份能跑、能通过验证的完整项目。你唯一要做的，是把它读懂。

## 2. 完成思路总览（这节最重要，请读两遍）

### 2.1 核心思想：分而治之 + 每一层都能独立验证

做 SoC 最容易翻车的做法，是"一口气把所有模块写完，然后一起编译，报一堆错不知道从哪改"。

正确做法是自底向上、层层验证：

```
第 1 层：FIR 内核（纯算法）      实验 01~05    ← 已经做完
第 2 层：总线握手                实验 06       ← 先学会"怎么用总线"
第 3 层：FIR 挂上总线            实验 07       ← FIR 变成外设
第 4 层：完整 SoC + 软件驱动     实验 08 + sw  ← 拼装 + C 驱动
```

每一层都独立跑仿真、独立看结果，通过了再往上走。这样任何一步出错，都只可能是"这一层新加的那一点"出问题。

### 2.2 赛题要求的"三层验证"就是这个意思

赛题技术报告明确要求三个层级的验证，我们的项目正好对应：

1. 单元/模块验证：单独测一个模块（实验 01~05 测 FIR 各部件；实验 06 测 SRAM 从设备）。
2. 集成验证（不含 CPU 核）：把若干模块连起来，用 Testbench 当"假 CPU"去访问（实验 07 用 BFM 驱动 FIR；实验 08 用 BFM 驱动整个 SoC）。
3. 系统测试（含 CPU 核，写 C 驱动）：真 CPU 跑 C 代码（`sw/main.c`；仿真里用 BFM 重放同一套寄存器操作）。

### 2.3 软硬件怎么"对得上"：一份合同走天下

软硬件协同最容易出错的地方是"两边各说各话"。解决办法是一份寄存器映射（内存地图）当合同：

- 硬件侧：`rtl/fir_axi.v`、`rtl/uart_axi.v`、`rtl/axi_lite_xbar.v` 里的地址常量。
- 软件侧：`sw/fir_regs.h` 里的宏定义。
- 黄金模型：`gen_fir_vectors.py` 用同样的定点约定算出"标准答案"。

三边都以同一张表为准，谁都不许改。这张表就是：

| 外设 | 基地址       | 关键寄存器                                 |
|---   |------       |
| FIR  | 0x0000_0000 | 0x004 写样本、0x008 读结果、0x100+4k 写系数 |
| UART | 0x0000_1000 | 0x000 写字节、0x004 读忙标志               |
| SRAM | 0x0000_2000 | 普通读写                                   |

## 4. 关键概念，用大白话讲

### 4.1 时钟、复位、posedge、非阻塞赋值（数字电路的地基）

- 时钟 clk：一条周期性"跳一下"的电线，整个系统都踩着它的节拍走。
- 复位 rst_n：按下它，所有寄存器清零，回到确定状态（所以波形里不会出现乱七八糟的 X）。
- `always @(posedge clk)`：每当时钟从 0 跳到 1 的那一刻，执行里面的语句。这就是"时序逻辑"。
- 非阻塞赋值 `<=`：在一个 `posedge` 里写的值，要等这个上升沿结束才生效。
  它保证"大家同时更新"，是写对时序电路的第一条铁律（实验 01 专门练这个）。

### 4.2 定点数 Q1.15（FIR 里所有数怎么表示）

FPGA 里没有小数，只有整数。我们用"定点数"来表示 -1 ~ +1 之间的小数：

```
真实值 = 整数 / 2^15  = 整数 / 32768
```

所以：`1.0 → 32767`，`0.5 → 16384`，`-1.0 → -32768`。
数据 16bit、系数 16bit 都是 Q1.15。

为什么要右移 15 位：两个 Q1.15 相乘 = `(X/2^15)*(H/2^15) = X*H/2^30`，
累加后要回到 Q1.15，就得再除以 2^15，也就是右移 15 位。
（对应 `fir_cfg.v` 里的 `SHIFT = CW-1 = 15` 和 `gen_fir_vectors.py` 里的 `>> 15`。）

### 4.3 FIR 是什么（一句话 + 一张图）

FIR 滤波器就是一条移位寄存器（延迟线），每个位置的数据乘一个系数，再加起来：

```
输入 x ──> [x0] ──> [x1] ──> [x2] ──> ... ──> [x80]
            │        │        │                │
          × h0     × h1     × h2     ...     × h80
            └────────┴────────┴────── ... ──────┘
                            Σ（求和）──> 输出 y
```

- 延迟线就是实验 02 的移位寄存器（81 阶 = 80 级延迟）。
- 每个抽头乘系数再求和就是实验 03 的乘累加（MAC）。
- 系数对称（h[k]==h[80-k]）带来"线性相位"这个好性质，也是决赛"81→41 次乘加"优化点。

### 4.4 为什么累加器要 40 位（初赛最容易翻车的点）

最坏情况：81 项，每项 = 32768 × 32768 ≈ 1.07×10^9。
81 项加起来 ≈ 8.7×10^10。

- 32 位最大只能到 2.1×10^9 → 一定溢出，负数会"回绕"成尖峰。
- 40 位最大到 1.1×10^12 → 够用。

所以 `fir_cfg.v` 里累加器 `AW=40`。这个细节在实验 03 里专门练过。

### 4.5 总线握手 valid/ready（实验 06 的核心）

CPU 和外设之间传数据，用"握手"来对齐节奏。规则只有一条：

> 发数据的一方拉高 valid（"我准备好了"），收数据的一方拉高 ready（"我也准备好了"），
> 当 valid 和 ready 在同一个时钟上升沿同时为 1，这次传输就完成。

AXI 有 5 个通道（写地址、写数据、写响应、读地址、读数据），
每个通道都是这套 valid/ready 握手。**看懂实验 06 的 `tb_axi_sram.v` 里两个 task，
就等于看懂了 AXI 的一半。**

### 4.6 寄存器映射 / 内存地图（CPU 怎么控制外设）

CPU 眼里没有"外设"，只有一长串地址。读写某个地址，就是控制某个外设：

- 写 `0x0000_0100` → 就是在配置 FIR 的第 0 个系数。
- 写 `0x0000_0004` → 就是喂给 FIR 一个样本。
- 读 `0x0000_0008` → 就是取走一个滤波结果。
- 写 `0x0000_1000` → 就是让 UART 发一个字节。

这就是"内存映射 IO"，`sw/fir_regs.h` 把每个地址起了名字，C 代码看起来就很好懂。

### 4.7 为什么 FIR 和 CPU 之间要一个 FIFO（实验 07 的关键）

FIR 是"流式"的：每个时钟都能吐一个结果。
CPU 是"拍"的：通过总线读一次要好几拍握手。

两边节奏不匹配，就在中间垫一个 FIFO（先进先出队列） 当缓冲池：
FIR 往里写，CPU 从另一头读，谁也不等谁。`rtl/sync_fifo.v` 就是它。

## 9. 已经做完 & 还差什么

已经做完（09/10 补上了赛题两大块）：

- 真 Cortex-M0（实验 09）：赛题指定 CPU 已接进 SoC，能跑 C 程序控制 FIR。
  细节见 [`Cortex-M0集成说明.md`](Cortex-M0集成说明.md)。
- 6 通道 DMA（实验 10）：`rtl/dma.v` 独立验证 PASS。

还差（决赛加分项 & 真正上板，按性价比排序）：

1. 修 09 的循环计数 bug：真核已跑通，但滤波数值输出全是 0（循环变量不递增），
   这是当前唯一没闭环的功能点。
2. 多主仲裁 + DMA 接入 SoC：DMA 是"主设备"，要和 CPU 同时访问总线，就需要在互连里
   加"仲裁"（两个主同时要访问时让谁先），并把 DMA 挂进 `soc_cm0_top.v`。
3. FIR 对称优化（决赛明示的 20 分方向）：利用 h[k]==h[NTAP-1-k]，
   先算 `x[k]+x[NTAP-1-k]` 再乘，乘法器从 81 个降到 41 个。
4. 上板（紫光同创 Logos-2）：我们的 RTL 都是可综合风格（全同步、寄存器化、
   无 `initial`/`$display` 等仿真专用语句在 rtl 里），但要注意——
   81 项加法串成一条组合链，50MHz 大概率时序不过；要过时序得把累加改成
   流水线加法树（成对相加、每级打拍）。这是"功能正确"和"能上板"之间的一步。
5. UART 回显：现在只有 TX（发）。补一个 RX（收），就能做赛题要求的"UART 回显"。
