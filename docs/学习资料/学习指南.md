## 一、赛题在考什么

飞腾出的题，本质是做一个东西：一颗 Cortex-M0 加一条 AXI 总线，加一个 81 阶 FIR 滤波器、一个 UART、一个 6 通道 DMA，让 CPU 用 C 程序配置滤波器、搬数据、读结果。

听起来吓人，但拆开每一块都不难。真正难的是总线——不是概念难，是细节多，握手错一拍就死锁。

初赛看功能对不对、文档清不清楚，**完全不看性能**；决赛才比吞吐量、资源占用和架构创新。所以初赛的策略很明确：先做一个功能完整、逐位正确的版本。

| 赛题要求 | 本项目对应 | 能学到什么 |
|---|---|---|
| 81 阶 FIR，≥1 sample/cycle | `RTL/fir_core.v` + `RTL/fir.v` | FIR 原理、定点数、并行乘累加 |
| AXI 互连、多主仲裁、单拍与突发 | `RTL/axi_ic.v` + `RTL/axi_arbiter.v` | 总线握手、地址译码、仲裁 |
| 桥 | `RTL/ahb2axi.v`、`RTL/axi_to_apb.v` | 协议转换 |
| UART | `RTL/uart_apb.v` + rx + tx | 串口协议、外设寄存器 |
| CPU | `RTL/cpu/cortexm0ds/` + `RTL/soc_top.v` | 向量表、真 CPU 跑 C 程序 |
| 6 通道 DMA | `RTL/dma.v` + `dma_regs.v` + `dma_engine.v` | AXI 主设备、搬数据状态机 |
| 软硬协同 | `sw/` 四个文件 | C 驱动怎么写 |

## 二、完成思路：分而治之，每层独立验证

做 SoC 最容易翻车的做法是"一口气把模块全写完，然后一起编译，报一堆错不知道从哪改"。

正确做法是自底向上、层层验证。这个项目就是这么长出来的：

```
第 1 层  FIR 内核（纯算法，无总线）        RTL/fir_core.v
第 2 层  FIR 的 AXI 外壳                  RTL/fir.v
第 3 层  总线握手与互连                    RTL/axi_ic.v + axi_arbiter.v
第 4 层  桥接（AHB→AXI、AXI→APB）          RTL/ahb2axi.v + axi_to_apb.v
第 5 层  完整 SoC + 固件                   RTL/soc_top.v + sw/
第 6 层  DMA 与软硬协同                    RTL/dma*.v + sw/main.c
```

每层都独立跑仿真、独立看结果，通过了再往上走。这样任何一步出错，都只可能是这一层新加的那点东西有问题。这个原则在调试阶段救过很多次——一个总线故障如果发生在整个 SoC 里，排查成本是单模块阶段的十倍。

赛题技术报告要求的三层验证正好对应这个结构：单元/模块验证（每个模块单独测）、集成验证不含 CPU（`tb_phase5_integration`）、系统测试含 CPU（`tb_soc`、`tb_phase6_fir_dma`）。

## 三、软硬件怎么"对得上"

协同设计最容易出错的地方是两边各说各话。解决办法是一份寄存器映射当合同：

- 硬件侧：`RTL/fir.v`、`RTL/uart_apb.v` 里的地址译码常量
- 软件侧：`sw/main.c` 里的宏定义
- 黄金模型：`fir/fir_coeff.py` 用同样的定点约定算标准答案

三边以同一张表为准，谁都不许改。这张表在 `../任务3-地址映射与中断分配.md`：

| 外设 | 基地址 | 关键寄存器 |
|---|---|---|
| FIR | `0x4000_0000` | `0x004` 写样本、`0x008` 读结果（读即弹出）、`0x100+4k` 写系数 |
| DMA | `0x4000_1000` | 每通道 4 个寄存器：SRC/DST/LEN/CTRL |
| UART | `0x4000_2000` | `0x000` 写字节、`0x004` 状态 |
| SRAM | `0x0000_0000` | 普通读写，64KB |

## 四、几个关键概念

### 4.1 时钟、复位、非阻塞赋值

时钟是一条周期性跳变的线，整个系统踩着它的节拍走。复位把寄存器清零，回到确定状态——没有复位，波形里会全是 X。

`always @(posedge clk)` 表示时钟上升沿到来时执行，这就是时序逻辑。非阻塞赋值 `<=` 保证"所有寄存器同时更新"，这是写对时序电路的第一条铁律。

这条铁律为什么重要，有个具体例子：测试台里撤 `valid` 必须用 `<=` 而不是 `=`，因为阻塞赋值会在当前时刻立刻生效，早于从设备采样，造成竞争。

### 4.2 定点数 Q1.15

FPGA 里没有小数，只有整数。用定点数表示 -1 到 +1 之间的值：

```
真实值 = 整数 / 2^15
```

所以 `1.0 → 32767`、`0.5 → 16384`、`-1.0 → -32768`。数据和系数都是 16 位 Q1.15。

两个 Q1.15 相乘得到 Q2.30，累加后要回到 Q1.15，就得右移 15 位。这对应 `fir_core.v` 里的 `SHIFT = CW - 1`，也对应 `fir/fir_coeff.py` 里的 `>> shift`——两边必须用同一个规则，否则逐位比对永远过不了。

### 4.3 FIR 是什么

一条移位寄存器（延迟线），每个位置的数据乘一个系数再加起来：

```
x ──> [x0] ──> [x1] ──> ... ──> [x81]
        × h0     × h1            × h81
        └────────┴───── Σ ────────┘  → y
```

"81 阶"指多项式阶数，对应 82 个抽头和 81 级延迟。代码里 `NTAP = 82`，文档里说"81 阶"，是同一件事。

系数对称是线性相位滤波器的性质，也是决赛"82 抽头压到 41 次乘加"优化的依据。

### 4.4 为什么累加器要 40 位

最坏情况是把输入和系数都推到负满幅，每个乘积都是 2^30，82 个加起来约 8.8×10^10。

32 位最大只到 2.1×10^9，一定溢出，负数会回绕成尖峰。38 位是理论下限，本项目取 40 位留 2 位余量。

这个细节有个坑值得记住：如果只按"当前这组系数"估，32 位就够用。但系数是可配置的，CPU 运行时可写任意值，所以必须按全摆幅设计。详细推导在 `../任务5-FIR定点方案说明书.md`。

### 4.5 总线握手 valid/ready

规则只有一条：发送方拉高 `valid`（我准备好了），接收方拉高 `ready`（我也准备好了），两者在同一个上升沿同时为 1，这次传输完成。

AXI 有 5 个独立通道（写地址、写数据、写响应、读地址、读数据），每个通道都是这套握手。看懂一个通道，剩下四个是重复的。

这里有条铁律必须记牢：**`valid` 拉高后不许等 `ready` 才有效，也不许撤销**。违反它会直接死锁，而且现象很难看——仿真跑不动，波形里两个信号互相等。

### 4.6 寄存器映射

CPU 眼里没有"外设"，只有一长串地址。读写某个地址就是控制某个外设：写 `0x4000_0100` 是配第 0 个系数，写 `0x4000_0004` 是喂一个样本，读 `0x4000_0008` 是取一个结果。

这就是内存映射 IO。`sw/main.c` 里给每个地址起了名字，C 代码看起来就好懂多了。

### 4.7 FIR 和 CPU 之间为什么要有 FIFO

FIR 是流式的，每个时钟吐一个结果。CPU 是拍式的，通过总线读一次要好几拍握手。两边节奏不匹配，中间就垫一个 FIFO 当缓冲池：FIR 往里写，CPU 从另一头读，谁也不等谁。

`RTL/sync_fifo.v` 就是它。深度定在 512，因为一次 DMA 搬运最多 338 个样本，留足余量避免反压。

## 五、怎么跑起来

```powershell
sim\sim.cmd                    # 跑全部 26 个测试台
sim\sim.cmd -List              # 先看看有哪些台
sim\sim.cmd -Only fir          # 只跑 FIR 相关的
```

判据只有一条：最后一行是 `===== 全部通过：26 个测试台 =====`。详细用法和排错见 `../怎么跑仿真.md`。

想自己换系数或抽头数：

```powershell
python fir\fir_coeff.py --taps 82 --cutoff 0.12 --nsamp 256 --outdir fir
```

改了抽头数要同步三处：`fir_core.v` 的 `NTAP`、`fir_coeff.py` 的默认 `--taps`、以及重新生成的 `sw/fir_testvec.h`。不一致的典型现象是端到端比对全部错位。

## 六、建议的学习顺序

原则是：跑通一个 → 读懂它的每一行 → 故意改错看它怎么报错 → 再进下一个。

**先花两小时建立全局观。** 读 `../赛题全景与行动手册.md`，再看 `../契约/契约1-接口契约（冻结版）.md` 搞清模块边界。别急着看代码。

**第一周：FIR 内核。** 从 `RTL/fir_core.v` 开始。这是纯算法，没有总线，最容易建立信心。对着 4.3 节的图看延迟线和乘法器，对照 `tb_fir_core.v` 看它怎么和黄金模型比对。目标是能回答三个问题：为什么系数对称？为什么右移 15 位？为什么累加器 40 位？

**第二周：总线。** 这是真正的门槛。从 `RTL/axi_sram.v` 入手（最简单的 AXI 从设备），死磕 `TB/axi_sram.v` 里的读写 task。然后看 `RTL/axi_ic.v` 怎么做地址译码和仲裁。目标是能默画一次"写"的时序图，说清 valid/ready 怎么交替。

**第三周：拼装。** 看 `RTL/soc_top.v` 怎么把九个模块连起来，`RTL/ahb2axi.v` 怎么把 AHB 翻译成 AXI。再打开 `sw/main.c`，对照 `tb_soc.v`，你会发现 C 代码里的每一步都能在测试台里找到对应。

**第四周：软硬协同。** `sw/main.c` 里的 `phase6_fir_dma()` 是整套系统的核心流程：配系数 → flush → DMA 搬样本 → DMA 搬结果 → 逐位比对。看懂它，就理解了"软硬协同"这四个字的含义。
