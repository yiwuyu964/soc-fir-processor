## 0. 先搞清楚 GTKWave 在流程里是什么位置

```
  你的 .v 代码
       │  iverilog 编译
       ▼
    sim.out  ──vvp 运行──▶  tb_xxx.vcd  ──▶ GTKWave   → 图形波形

                    同时 vvp 还会打印 TB 里的 $display（PASS/FAIL、每一拍的值）
```

关键认识：VCD 就是一个"流水账"文本文件，内容是信号值随时间的变化。GTKWave 只是把这个流水账画成图。所以"看不懂 GTKWave"，很多时候其实是"不知道 VCD 里到底记录了哪些信号"。

第一步建议先搞清楚文件里有什么，别急着开图形界面：

```powershell
Select-String -Path "<波形目录>\tb_dma.vcd" -Pattern '^\$var' | Select-Object -First 20
```

`$var` 行就是信号声明，能看到名字、位宽、内部编号。知道有什么，才知道该看什么。

最容易卡住的一点：

> 打开 GTKWave 时 ② 号栏是空的，所以你看到一个空白窗口，以为软件坏了。
> 不是坏了，是还没把信号"加进来"。见下面操作 1。

## 2. 六个必会操作

### 操作 1 —— 把信号加进来（最重要的一步）

双击 ① SST 树里的信号名 → 它自动加到 ② 栏 → ③ 区立刻画出波形。

- 信号太多找不到？在 SST 下方的 Filter 框里输入名字（支持正则），树会自动过滤。
- 一次加一批：按住 `Ctrl` 或 `Shift` 多选，然后用鼠标左键把它们拖进 ② 栏。
- 加错了：在 ② 栏点中信号（高亮），按 `Delete` 删掉。
- 找不到 SST 面板？菜单里找 `Search → Signal Search Tree`（有的版本叫 `Tree Search`）。

### 操作 2 —— 放大 / 缩小 / 平移

| 想要的效果 | 怎么操作 |
|---|---|
| 放大 | Alt + 滚轮向下 |
| 缩小 | Alt + 滚轮向上 |
| 左右平移 | Ctrl + 滚轮 |
| 只看某一段 | 在 ③ 波形区按住右键拖一个框，松开即放大到该范围 |
| 一下子看全部 | 菜单 `Time → Zoom Best Fit`（或工具栏那个方形按钮） |
| 回到最开头 | 菜单 `Time → Zoom To Start` |

> 刚打开时波形经常挤成一条红线 —— 这不是没数据，是没缩放。先 `Time → Zoom Best Fit`。

### 操作 3 —— 量时间差（"延迟几拍"就这么测）

1. 在 ③ 波形区点一下左键 → 放下红色主标记（Primary Marker）
2. 在 ③ 波形区点一下中键（滚轮按下去）→ 放下白色基准标记（Baseline Marker）
3. 两个标记都放下后，看顶部 `Marker Time` —— 它显示的是两者的时间差

这就是"`dout` 比 `din` 晚几拍"、"FIFO 延迟多少"的标准测法。

> 注意：只放主标记时 `Marker Time` 显示的是绝对时间；
> 一旦放了基准标记，它就切换成差值显示。想测延迟就必须放两个。

### 操作 4 —— 把值看清楚（尤其是负数）

放下主标记后，② 栏每个信号名右边会出现 `=` 和该时刻的值。

- 默认是十六进制，负数会显示成补码（比如 `-1000` 显示成 `FC18`）
- 想看有符号十进制：在 ② 栏点中信号 → 菜单 `Edit → Data Format → Signed`
- 其它进制：`Edit → Data Format → Hex / Decimal / Binary / ASCII`
- 信号名右边的格式标志：`+` = 有符号十进制，`X` = 十六进制，`D` = 十进制

> 嫌麻烦的话，把常用的那几个信号一次性设好格式，然后存成 `.gtkw`，下次直接读回来。

### 操作 5 —— 看细节的两个开关

- `View → Show Mouseover`：鼠标划过波形时浮出"信号名 = 值"的小提示（很省事，建议一直开着）
- `Edit → Insert Blank`：在当前行下面插一条空白分隔线，把信号按功能分组（时钟组 / 控制组 / 数据组）
- `Edit → Insert Comment`：插一行文字注释

### 操作 6 —— 保存布局，省得每次重加信号

`File → Write Save File As` → 存成 `.gtkw` 文件。

下次 `File → Read Save File` 就能恢复"哪些信号、什么进制、缩放位置、标记位置"。
也可以命令行一次打开：

```powershell
gtkwave tb_dma.vcd my.gtkw
```

## 3. 几个测试台分别该看什么

本节说的是"打开某个波形后应该看到什么"，用来检验自己有没有看对地方。

### `tb_fir_core` —— FIR 数据通路

加的信号：`clk`、`rst_n`、`en`、`din[15:0]`、`dout[15:0]`、`dout_v`

| 该看到的现象 | 说明 |
|---|---|
| `en` 拉高后 `dout_v` 晚 5 拍才变高 | 流水线深度 `LAT=5`，这是契约写死的 |
| 刚开始的几十个样本，`dout` 都很小 | 暂态，延迟线还没填满，别在这里判对错 |
| 稳定后 `dout` 的包络比 `din` 平滑 | 高频分量被滤掉了，这就是滤波 |
| `dout_v` 每拍都是高的 | 全并行结构，吞吐 1 sample/cycle |

想深入看：在 SST 里展开 `dut`，把 `x[0]`、`x[1]`、`x[2]` 加进来，能看到样本一个接一个往右挪——这就是延迟线在工作。

### `tb_dma` —— 总线握手

加的信号：`h_htrans[1:0]`、`h_hwrite`、`h_hready`、`b_awvalid`、`b_awready`、`b_wvalid`、`b_wready`、`b_wlast`

| 该看到的现象 | 说明 |
|---|---|
| `awvalid` 和 `awready` 同拍为高的那一拍，地址被接受 | 这就是一次握手成功 |
| `awvalid` 拉高后一直保持，直到 `awready` 变高 | VALID 不许撤销，违反会死锁 |
| `wlast` 只在突发最后一拍为高 | 标出突发结束 |
| 连续传输之间没有空拍 | AHB 流水线特性，背靠背传输 |

要理解的点：GTKWave 里最容易看出来的错误就是握手——`valid` 拉高后如果 `ready` 一直不来，那多半是对端有 bug 或者死锁了。

### `tb_soc` —— CPU 跑起来是什么样

加的信号：`h_htrans`、`h_haddr[31:0]`、`h_hwrite`、`uart_txd`

| 该看到的现象 | 说明 |
|---|---|
| 复位释放后 `h_haddr` 在 `0x0` 附近反复变化 | CPU 在取指、读向量表 |
| `h_haddr` 会跳到 `0x4000_0000` 一带 | CPU 在访问 FIR 外设 |
| `uart_txd` 出现规整的高低电平序列 | 串口在发数据，每一位宽度等于 `UART_DIV` 个时钟 |

### `tb_phase6_fir_dma` —— 端到端全流程

这个台要跑八万多拍，波形文件有 8 MB 左右。看的时候别从头看，直接跳到 `MB[6]` 变成 `0x1000` 之后——那是固件写完"阶段六完成"标志的时刻，之前全是配置和搬运。

| 该看到的现象 | 说明 |
|---|---|
| 前半段 `h_haddr` 密集访问 FIR 的 `0x4000_0100` 起 | CPU 在写 82 个系数 |
| 中间段 DMA 的 `b_awvalid` 成串出现 | DMA0 在搬样本，DMA1 在搬结果 |
| 结尾 `h_haddr` 访问 SRAM 的 `0x0F00` 附近 | CPU 在写信箱结果 |

## 5. 常见困惑对照表

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| 打开是一片空白 | 信号还没加进来（② 栏是空的） | 双击左侧 SST 里的信号名 |
| 波形挤成一条红线 | 没缩放，全部时间压在一屏里 | `Time → Zoom Best Fit` |
| 波形是一片红色实心块 | 时间跨度太大，跳变密到看不清 | 右键拖框放大到感兴趣的一段 |
| 信号值显示成 `FC18` 而不是 `-1000` | 默认十六进制，补码形式 | `Edit → Data Format → Signed` |
| `acc` 显示成很大的正数 | 同上，无符号解释 | 同上，改进制为 Signed |
| 找不到某个信号 | 名字在不同层次下 | 在 SST 里展开对应层次；或直接搜 VCD 里的 `$var` 行看全名 |
| 信号确实不存在 | TB 里没 `$dumpvars` 它 | 在 TB 的 `$dumpvars` 里加上，或改 `$dumpvars(0, tb_xxx)` |
| 关掉后下次又得重新加信号 | 没保存布局 | `File → Write Save File As` 存 `.gtkw` |
| 波形开头一段值都是 `x` | 还没复位 / 还没给激励 | 正常现象，看复位释放以后的波形 |

## 6. 建议的练习方式

新手直接开 GTKWave 容易迷路，建议这样练：

先跑一个小的、信号少的台，比如 `sim\sim.cmd -Only fir_core -KeepVcd`。它跑得快、波形小，适合熟悉界面。

打开后按第 2 节的操作 1 把三五个信号加进来，缩放、放标记、改进制都试一遍。界面熟了再去看大的台。

碰到看不懂的现象，先用第 5 节那张表对照——大部分"看起来不对"其实是没缩放或者没加信号。

真正的调试顺序应该是：先看 `$display` 打印的 PASS/FAIL 知道哪一项失败了，再带着具体问题去波形里找对应时刻的信号。没有目标地翻波形是最费时间的。
