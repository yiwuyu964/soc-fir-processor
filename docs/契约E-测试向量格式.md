# 契约 E：测试向量格式（C 生成，A/B 消费）

> **文档信息** ｜ 类别：契约类 ｜ 所属：跨阶段 ｜ 状态：冻结 ｜ 索引：`docs/README.md §1.1`
> 本契约定义 FIR 测试向量 `stim.hex`（激励）与 `exp.hex`（期望输出）的文件格式。
> C 生成、A/B 消费。依据：[契约1-接口契约（冻结版）.md](契约1-接口契约（冻结版）.md) 契约 A（`DW=16`、`AW=40`、A6 定点规则）、契约 D（系数文件）、C 任务（`--nsamp 256`）。
> 版本：v2，81 阶 / 82 抽头；比赛误差口径采用 RRMSE（相对均方根误差）< 0.1%，定点逐位比较另行保留。

---

## E.0 范围

- 本契约只定义两个文件：`fir/stim.hex`、`fir/exp.hex`。
- **浮点参考（真实数学答案）不写成 .hex**，由 `fir_coeff.py` 内部计算并输出到误差报告（可选导出 `exp_float.txt`）。

## E.1 样本精度与量化

- 样本位宽 16bit，定点格式 Q1.15：`浮点值 = 整数 / 32768`。
- `stim`：整数 ∈ [-32768, 32767]。
- `exp`：整数 ∈ [-32768, 32767]（饱和后）。

## E.2 文件格式（与契约 D 的 `coeffs.hex` 同规则）

- 每行**恰好 4 个十六进制字符**（16bit 二进制补码），无前缀、无注释、无分隔符。
- 一行一个样本，按时间顺序：第 1 行 = 样本 0。
- 末尾允许且仅允许一个换行符。

```verilog
// 消费方式（NSAMP=256、NTAP=82）
reg [15:0] stim_mem [0:NSAMP-1];         // 256 个
reg [15:0] exp_mem  [0:NSAMP+NTAP-2];    // 256+82-2=336，共 337 个
$readmemh("fir/stim.hex", stim_mem);
$readmemh("fir/exp.hex",  exp_mem);
// stim_mem[n] == x[n]      （n=0..NSAMP-1）
// exp_mem[n]  == y_full[n] （n=0..NSAMP+NTAP-2）
```

## E.3 样本数与对齐（**全卷积**，非零填充）

- `stim.hex`：`NSAMP` 行（默认 256），第 n 行 = x[n]（n=0..NSAMP-1）。
- `exp.hex`：**`NSAMP + NTAP - 1` 行**（默认 256+82-1=337），全卷积结果。
- `exp[n] = y_full[n] = Σ_{k=0}^{81} h[k]·x[n-k]`，其中 **x[m]=0（m<0 或 m≥NSAMP）**。
- **全卷积含义**：喂完 NSAMP 个样本后，再灌 NTAP-1 个 0 把延迟线排空，收齐全部 NSAMP+NTAP-1 个输出（最后 NTAP-1 个「尾部」输出仍非零）。
- 与「零填充」的区别：零填充只给前 NSAMP 个输出（x[n<0]=0）；全卷积**额外多给尾部 NTAP-1 个排空输出**。

## E.4 `exp.hex` 是「定点逐位参考」（不是浮点、不是全精度累加器值）

- `exp.hex` 存的是 RTL 输出 `dout` 应有的 **16bit 饱和值**，A/B 的 TB 直接比对。
- **定点参考计算路径**（黄金模型必须严格复刻 RTL，共 5 步）：
  1. 系数取 `coeffs.hex` 的 16bit 整数；
  2. 输入取 `stim.hex` 的 16bit 整数；
  3. 全精度累加（Python `int`，不截断、不饱和中间量）：`acc[n] = Σ_{k=0}^{81} coef[k]·x[n-k]`；
  4. 输出：`y_out[n] = clamp(acc[n] >> 15, -32768, 32767)`，其中 `>> 15` 为**算术右移（floor）**，与契约 A6「右移 15 位 + 饱和」一致；
  5. 写成 4 位十六进制补码，n = 0..NSAMP+NTAP-2。
- 累加器 AW=40 不溢出：最大 `82 × 2^30 ≈ 2^36.3 < 2^39`，中间量无需饱和，**只有最后一步饱和**。

## E.5 定点规则已由契约 A6 冻结（无需再确认）

- 契约 A6：「乘积 Q2.30 精确，累加 40bit 不溢出，输出**右移 15 位**回 Q1.15 并饱和」。
- 「右移 15 位」= 算术右移（floor），与 E.4 第 4 步的 `acc >> 15` 等价（二补码下丢弃低 15 位即 floor）。
- 契约 A 的自检台还含「最坏情况应正饱和到 +32767」用例（专抓 32bit 累加回绕），证明累加必须 ≥40bit，与 E.4 的「AW=40 不溢出」一致。

## E.6 流水线延迟与比对约定（消费约定，不是文件内容）

- `fir_core` 延迟**恰 5 拍**：`din[n]` 进 → `dout[n]` 在第 5 拍后有效（`dout_v=1`）。
- TB 流程：flush 后，喂 NSAMP 个样本，再喂 NTAP 个 0（包含推动前导零的一拍），共收 NSAMP+NTAP 个 `dout_v`。
- **比对约定**（A、B 都按这个写，来自冻结版契约 D）：
  - 第 1 个 `dout_v` = **前导 0**（全零输入的卷积结果）；
  - 之后 `got[i+1] == exp[i]`（i = 0..NSAMP+NTAP-2）。
- ⚠️ 前导 0 是否出现取决于 A 的流水线/延迟链结构：A 实现后跑契约自检台确认；若第 1 个 `dout_v` 直接就是 `exp[0]`（无前导 0），则改成 `got[i] == exp[i]` 并在群里同步。

## E.7 激励设计建议（内容由 C 定，但要固定种子保证可复现）

- 建议复合激励：**带内正弦**（如 0.05·fs，验证通过）+ **带外正弦**（如 0.4·fs，验证衰减）+ **满幅正弦**（验证饱和）。
- 幅度统一缩放到 Q1.15 范围内不溢出；随机部分用**固定随机种子**。
- 生成后 `stim.hex` 与 `exp.hex` 一并提交；任何人改激励都要重跑脚本。

## E.8 生成命令

```
python fir/fir_coeff.py --taps 81 --cutoff 0.12 --nsamp 256
```

输出：`coeffs.vh`、`coeffs.hex`、`stim.hex`（256 行）、`exp.hex`（336 行）+ 误差报告。
