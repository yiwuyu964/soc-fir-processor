## 0. 三句话说清这个比赛

1. 这是**"中国电子杯"第三届"四邮四电"高校 ICT 产教融合创新大赛**里，由**飞腾信息技术有限公司**出的赛题，名字叫
   **《带高阶 FIR 数字滤波器的 SoC 处理器设计》**。
2. 说白了就是：**在一块 FPGA 上，用一颗 Cortex-M0 的 CPU，通过 AXI 总线指挥一个硬件 FIR 滤波器干活。**
   CPU 负责"发号施令"（配置系数、下命令），FIR 硬件负责"埋头算"（做滤波），中间靠 DMA 搬数据，结果通过串口打印出来。
3. 评分看两轮：**初赛看"功能对不对 + 文档清不清楚"（不看性能）**，**决赛才拼性能、资源和创新**。
   所以初赛策略就一句话：**先做一个功能完整、能跑通、逐位正确的版本。**

### 2.2 逐条翻译成人话

| 赛题原话 | 人话 |
|---|---|
| "81 阶**可配置系数** FIR，全硬件实现，支持 AXI 接口" | 写一个滤波器的硬件电路。**系数要能被 CPU 在运行时改写**（不是烧死在代码里）。它要挂在总线上像个外设一样被读写 |
| "系数宽度 ≥16bit 定点，数据宽度 16bit，吞吐量 ≥1 sample/cycle" | 每个数用 16 位二进制小数表示。**每个时钟周期必须能算出一个结果**，不能"算一个歇三拍" |
| "AXI 互连 / 总线仲裁（支持多主设备），AHB→AXI、AXI→APB 接口的桥" | 造一条"总线"把各个模块连起来。**有多个设备同时想用总线时，要有个"交警"决定谁先走**。CPU 说的是 AHB 方言，总线说的是 AXI 方言，要有个"翻译" |
| "6 通道独立 DMA……支持传输完成后发起中断" | 一个"搬运工"模块，有 6 条独立通道，能在内存和 FIR 之间**不麻烦 CPU** 地搬数据，搬完举手报告（中断） |
| "软硬协同验证：提供 C 语言驱动程序，通过 CPU 配置 FIR 系数、下发 DMA 任务、读取滤波结果" | 写一段跑在 CPU 上的 C 程序，让 CPU 真的去指挥这套硬件干活 |
| "最终设计需在 FPGA 开发板上综合、布局布线、时序收敛，主频 ≥25MHz（目标 50MHz）" | 代码要能真的烧进 FPGA 芯片跑起来。**"时序收敛"的意思是：时钟跑得够快时，信号还来得及在一个周期内传完**（详见 [零基础名词详解.md](../fir_soc/零基础名词详解.md) 第 5 章） |

### 2.3 "FIR 滤波器"到底是什么（不懂信号处理也能懂）

想象你有一串数字，比如麦克风每秒采 8000 次得到的音量值。其中混着你要的人声（低频）和你不想要的嘶嘶声（高频）。

**FIR 滤波器就是一个"滑动平均器"**：它每次取最近 81 个采样点，每个点乘一个预设的权重（叫**系数**），然后全部加起来，得到一个新的数。

```
输出[n] = 系数[0]×样本[n] + 系数[1]×样本[n-1] + ... + 系数[80]×样本[n-80]
```

- **系数选得好** → 高频部分被抵消掉，低频保留 → 这就是"低通滤波"
- **"81 阶"** = 用了 81 个系数 = 每次要算 81 次乘法再相加
- **为什么要用硬件做？** 因为采样率是 200 MHz 级别的，每秒要算 200M × 81 ≈ 160 亿次乘法，CPU 用软件算根本来不及。**做成专用电路，每个时钟周期算一个，就快了。**

> 更详细的 FIR 讲解见 [学习指南.md](../fir_soc/学习指南.md) §4.3、[零基础名词详解.md](../fir_soc/零基础名词详解.md) 第 3 章。

## 3. 你的背景评估：缺什么、不缺什么

你的情况：**没有模电、数电基础，稍微接触过 FPGA 仿真。**

好消息是，这个赛题对基础的要求比你想的低得多：

| 你以为需要的 | 实际需要吗 | 说明 |
|---|---|---|
| **模拟电路**（运放、三极管、KCL/KVL、电路分析） | ❌ **完全不需要，一点都用不上** | 这是纯数字设计。赛题从头到尾没有一个模拟器件 |
| **数字电路** | ⚠️ **只需要很小一部分** | 只需要懂 5 个概念：**0/1、逻辑门、组合逻辑、时序逻辑、时钟与寄存器**。[零基础名词详解.md](../fir_soc/零基础名词详解.md) **第 1 章**就是专门写这个的，看完就够用 |

| **FPGA 仿真** | ✅ **你已经会了最重要的那一半** | 这个项目 80% 的日常工作就是：**改代码 → 跑仿真 → 看波形 → 比对结果**。你接触过仿真，等于已经过了最陡的那道坎 |

**结论：你最大的短板是"总线协议"和"Verilog 熟练度"，而不是你担心的模电数电。**
模电请直接从你的待办清单里划掉。
