# 阶段5：单元验证与不含 CPU 的集成验证

> **文档信息** ｜ 类别：验证与报告类 ｜ 所属：阶段 5 ｜ 状态：快照 ｜ 索引：`docs/README.md §1.4`
## 范围与验收口径

本阶段验证生产 RTL 的模块功能和模块间数据通路，不以软件运行或 CPU 启动代替集成验收。CPU 启动和 UART 软件回显仍由 `tb_soc` 回归守护，属于额外检查。

必达标准：所有指定测试通过；独立黄金模型逐项比较通过；协议检查器无非预期错误；必达功能 bins 全部命中；报告逐文件列出自动代码覆盖及未覆盖行。代码覆盖与功能覆盖分别报告，不能互相替代。商用工具的分支、条件、翻转覆盖没有可用结果时明确记为未获得。

## 测试矩阵

| 对象 | 正常与边界 | 激励、参考和检查 | 对应测试 |
|---|---|---|---|
| FIR core | 冲激、随机输入、连续/间断使能、flush、系数保留、饱和 | Python 定点黄金模型；5 拍延迟和数据有效对齐 | `tb_fir_core`、`tb_fir_core_contract` |
| FIR AXI | 系数突发、FIXED 数据流、读空、FIFO 满、IRQ、WSTRB、错误地址、读背压 | 逐拍数据与响应比较；背压时载荷稳定 | `tb_fir` |
| AHB→AXI | 8 种 HBURST × byte/half/word；真实 WRAP 地址；短 INCR；BUSY；HREADY 等待；错误后恢复 | 数据相位驱动；存储器参考；ERROR 第一拍 HREADY=0、第二拍 HREADY=1；非法未对齐/超宽访问拒绝 | `tb_phase5_ahb`、`tb_ahb2axi` |
| AXI→APB | FIXED/INCR、WRAP 拒绝、AW/AR 并发、APB 等待、早期错误、突发超时 | APB 时序检查；全部 W/R 拍被消化；错误不丢事务 | `tb_axi_to_apb` |
| 仲裁器/FIFO | 无请求、晚到高优先级请求、背压锁定、轮转、公平性、非 2 次幂深度回绕 | 固定赢家顺序参考；完整写入/弹出序列 | `tb_fifo_arbiter`，真实 2 主/6 通道争用由集成测试补充 |
| DMA 配置/引擎 | 六通道、LEN=0、固定/递增、超过 256 字、4KB 拆分、错误、非对齐拒绝、IRQ、START 脉冲 | 源/目的存储器比较；AXI ID 契约；错误与完成互斥 | `tb_dma_engine`、`tb_dma_self`、`tb_dma` |
| SRAM | byte/half/word、各字节 lane、零选通、最大 INCR、FIXED 长度、末地址、重定位、非对齐 AXI、跨 4KB/越界/保留类型拒绝、R/B 背压 | 独立预期字、逐拍读回、错误后原数据不变 | `tb_phase5_sram`、`tb_axi_sram`、`tb_sram_offset` |
| AXI 互连 | 两主五从、不同从设备并行、同从设备争用、缺省从设备、读写突发 | CPU/DMA 响应 ID 回选；每个目的区域读回比较 | `tb_axi_ic`、`tb_dma_ic`、`tb_phase5_integration` |
| UART/APB | 真实 UART 绝对地址、发送、接收、回显、连续 SETUP、忙写拒绝、零选通、读空 | 串行帧重建与 APB 响应检查 | `tb_uart_echo`、`tb_uart_apb_edges` |

AHB 与 AXI 的未对齐语义不同：AHB 主设备必须自然对齐，错误输入验证要求桥明确拒绝；SRAM AXI 的合法未对齐 INCR 第一拍保留起始字节位置，后续拍从传输大小对齐的地址递增。不能把两种情况都标为“未对齐已覆盖”而省略预期行为。

## CPU-free 集成拓扑与端到端检查

`phase5_fabric` 独立实例化生产 `axi_ic`、`fir`、`dma`、`axi_sram`、`axi_to_apb`、`uart_apb`；没有实例化 `soc_top`、CPU 或 AHB 桥。`phase5_axi_master` 模拟 CPU 的 AXI 主端，只经总线访问寄存器和 SRAM。

1. 经互连写入 81 个 FIR 系数及输入 SRAM。
2. DMA ch0 把 256 个样本及 81 个尾零搬到 FIR DIN，源地址从 0xF00 起，实际跨 4KB 并由 DMA 分段。
3. CPU BFM 同时访问独立 SRAM 区，ch2 同时进行 SRAM→SRAM 搬运。
4. DMA ch1 从 FIR DOUT 搬回 337 个结果。每个结果逐项对照独立 Python 黄金文件，包含契约规定的前导零。
5. 六通道先全部配置、再启动；确认六个 BUSY 同时有效后逐项验收六组目的数据，避免把六次串行搬运误报为并发。
6. 注入读/写 DECERR，验证错误中断及终止；检查 LEN=0、未映射区域、预留 m2 区域，以及传输中复位后的总线恢复。
7. CPU、DMA、FIR 端口并挂协议检查器。等待时间按种子 1、7、23 改变，失败会保留具体 top、seed 和日志。

## 功能覆盖模型

`phase5_axi_coverage.sv` 提供原生 SystemVerilog covergroup/coverpoint：SIZE、BURST、长度、对齐、响应及五通道背压，并建 SIZE×BURST 交叉。AHB 独立 covergroup 覆盖 HBURST、HSIZE、HTRANS、HREADY、HRESP 与大小×突发交叉。

Icarus 不支持这些原生结构时，使用同一真实握手上的 `COV|scope|bin` 事件汇总必达矩阵。场景 bin 只有在对应数据/响应检查已完成后发出；用例本身未 PASS 时，运行器不接受它的覆盖结果。清单固定在 `sim/phase5.py`，报告同时列分母、缺失项和场景范围。

必达矩阵是本验证计划的场景和可达接口项；通用原生 covergroup 里的超宽 SIZE、保留类型、不同端口不支持的交叉组合仍保留诊断结果。两者不能混用百分比。仅命中 bin 也不能代替数据正确性比较。

## 自动代码覆盖与收敛流程

`--line-coverage` 使用 Icarus 编译器 `-pfileline=1` 的可执行位置作为分母，VVP 的 `trace on` 执行记录作为命中集合。对不同用例和实例按文件、行取并集，自动生成未覆盖行。它是“已展开配置的可执行过程语句行覆盖”，不覆盖连续赋值、完整分支结果、条件组合或信号翻转；不会冒充商用全代码覆盖。

覆盖跟踪不改 RTL 功能逻辑，只删除编译产物中 TB 的调试指令以减少跟踪量，并对跟踪运行再次检查 PASS/失败信息。统计器自身有含未执行分支的正/负向测试。

收敛顺序：运行 → 查看 `summary.json` 的 `missing_bins` 和每文件 `missing` 行 → 找对应行为 → 增加有独立预期的用例 → 重跑。不能通过删除 bin、排除失败用例或写死命中计数消除缺口。默认分支、参数配置、协议非法输入等剩余项需逐项说明，不能统一按“不可达”扣除。

## 工具和复现

```powershell
# 开源回归 + 功能覆盖 + 自动过程语句行覆盖
python sim/phase5.py --line-coverage --report docs/阶段5-覆盖率报告.md

# 可选：XSim 原生 covergroup + sbct 数据库；work-dir 必须是尚不存在的英文路径
python sim/phase5.py --line-coverage --native --work-dir C:/Windows/Temp/soc_phase5_new_run --report docs/阶段5-覆盖率报告.md

# 完整项目回归（额外包含 CPU/真实固件检查）
sim\sim.cmd
```

若本机使用 Clang 编译真实固件，可通过 `SOC_CLANG`、`SOC_LLD` 环境变量指定工具路径，与 `sw/build.py --clang/--lld` 参数等价；正常有 GNU Arm 工具链的机器不需要这些变量。

本机 XSim BASIC 可完成仿真并保存覆盖数据库，但 `xcrg` 生成代码覆盖报告会要求 PRO 许可。运行器保留许可证错误原文和数据库，报告标明受限，采用开源过程语句行覆盖作为可复现的代码指标。原生分支/条件/翻转的报告未获得时不写数值、不声称通过验收。

详细日志、JSON、原生数据库放在忽略的 `build/phase5/`，提交验证计划、生成的 Markdown 报告、测试台和运行器。查看报告中的源码摘要和缺口后，再决定是否增加测试或使用具有相应许可的环境补齐高级代码覆盖。
