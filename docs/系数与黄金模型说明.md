## 0. 这个脚本干什么

`fir_coeff.py` 是软硬之间的一道「数据接口」：它用软件算出一组系数和一组期望输出，
交给 A/B 的 Verilog 测试台去比对，从而证明 RTL 的 FIR 和软件黄金模型逐位一致。

它产出的四件东西：

| 文件 | 内容 | 谁消费 | 契约 |
|---|---|---|---|
| `coeffs.vh` | 82 个系数（Verilog `localparam`） | A 的 `fir_core` / TB | D.3 |
| `coeffs.hex` | 82 个系数（十六进制补码） | A/B 的 TB `$readmemh` | D.4 |
| `stim.hex` | 256 个输入样本 | A/B 的 TB | E |
| `exp.hex` | 337 个期望输出（全卷积） | A/B 的 TB | E |

## 1. 滤波器设计原理（窗函数法）

### 1.1 为什么用线性相位 FIR

赛题要求「81 阶可配置系数 FIR，系数宽度 ≥16bit」。FIR 相比 IIR 的优势正是天然稳定 + 可设计成严格线性相位。
线性相位意味着所有频率分量的群延迟相同，信号波形不失真（只有整体延迟），这对音频/传感等信号处理是硬需求。

线性相位的充分条件是系数对称：`h[k] = h[NTAP-1-k]`，本项目 `NTAP=82`，即 `h[k] = h[81-k]`。82 是偶数，**没有中心抽头**，41 对系数镜像对称，群延迟 = `(82-1)/2 = 40.5` 个样本，是半拍。（如果当初选 81 个抽头，群延迟才是整数 40 拍。）

### 1.2 窗函数法（理想低通 × 窗）

设计一个低通 FIR 的标准做法是「窗函数法」，即 `scipy.signal.firwin` 内部的算法：

1. 理想低通冲激响应（无限长、非因果）：
   ```
   h_ideal[n] = fc·sinc(fc·(n - M/2))
              = sin(π·fc·(n - M/2)) / (π·(n - M/2))      （n ≠ M/2）
              = fc                                          （n = M/2）
   ```
   其中 `M = NTAP-1 = 81`，`fc = 0.12`（归一化到 Nyquist，即实际截止 = 0.12 × fs/2 = 0.06·fs）。

2. 截断 + 加窗：理想冲激响应无限长，直接截断会产生吉布斯现象（阻带旁瓣大）。
   乘一个 Hamming 窗 `w[n] = 0.54 - 0.46·cos(2πn/M)` 把两端平滑衰减，压低旁瓣（阻带衰减约 -53dB）。

3. 直流增益归一化：把系数整体除以 `Σh`，使 `Σh = 1.0`。
   这样直流（0 Hz）增益恰为 1.0，满幅直流输入不会把输出放大——这是赛题「误差 < 0.1%」比对的前提（硬件与软件的参考尺度一致）。

### 1.3 为什么选 81 阶、截止 0.12

- 81 阶是赛题指定，对应 82 个抽头。抽头数是偶数，所以群延迟是 40.5 个样本的半拍延迟；这对功能没有影响，因为比对时整体对齐即可。
- 截止 0.12（归一化）是命令行默认值，可换；阶数越高过渡带越陡、阻带衰减越大，但硬件乘法器越多（面积越大），这是性能/面积折中。

## 2. Q1.15 定点量化原理

### 2.1 表示

Q1.15 是 16 位有符号定点：最高位是符号位，其余 15 位是小数位。
真值 = `整数 / 2^15 = 整数 / 32768`，范围 `[-1.0, 0.999969]`。

例：`0x4000 = 16384 → 0.5`；`0xC000 = -16384 → -0.5`。

### 2.2 量化公式

```
系数整数 = round(浮点系数 × 32768)，再钳位到 [-32768, 32767]
```

量化后直流增益 `Σh_int ≈ 32768`（默认 82 抽头、截止 0.12、Hamming 窗对应 32769，偏差约 +0.0031%，是逐系数量化的累积）。

### 2.3 为什么 16bit 够（误差预算）

| 误差源 | 量级 |
|---|---|
| 系数量化（±0.5 LSB） | 0.0015% |
| 输入量化（±0.5 LSB） | 0.0015% |
| 输出截位（1 LSB，算术右移 15） | 0.003% |
| 合计 | 约 0.006% ~ 0.02%，远小于赛题 0.1% |

## 3. 黄金模型原理（双参考）

黄金模型要回答两个问题：RTL 该输出什么（逐位一致）、真实数学答案是什么（误差基准）。
所以给两个参考：

### 3.1 定点参考（`exp.hex`，与 RTL 逐位一致）

完全复刻 RTL 的算术（契约 A6）：

```
acc[m] = Σ_{k=0}^{81} h_int[k] · x_int[m-k]        （Python int 任意精度，等价 40bit 不溢出）
y_fixed[m] = clamp( acc[m] >> 15, -32768, 32767 )   （算术右移 + 饱和）
```

- 乘积是 Q2.30（16×16），累加最大 `82 × 2^30 ≈ 2^36.4`，40bit 累加器不溢出（契约 A 的 AW=40）。
- `>> 15` 是算术右移（floor），与 Verilog 有符号 `>>>` 一致；Python 的 `>>` 对负数也是 floor，两者等价。
- 最后一步 `clamp` 复刻 RTL 的饱和逻辑。

### 3.2 浮点参考（真实数学答案）

用未量化的系数 `h_float` 和未量化的输入 `x_float` 做卷积：

```
y_float[m] = Σ_{k=0}^{81} h_float[k] · x_float[m-k]
```

这是「如果没有任何量化误差，理论上该是多少」。定点参考与它的差 = 全部量化误差。

### 3.3 全卷积（为什么 exp 是 337 = 256+82-1）

一个 81 阶（82 抽头）FIR 处理 256 个样本时，输出不是 256 个而是 256+82-1 = 337 个（全卷积长度）：

- 前 256 个：每进一个样本出一个结果；
- 后 81 个（尾部）：喂完最后一个样本后，延迟线里还残留 81 个历史样本，要继续灌 0 排空，这 81 个「尾部」输出仍非零。

测试台喂完 256 个样本后再灌 81 个 0，才能收齐 337 个结果，与 `exp.hex` 逐位对上。
（`x[m]` 越界一律当作 0，等价于 RTL 复位后延迟线全 0。）

## 4. 误差分析原理（为什么「占满量程 < 0.1%」是正确口径）

脚本打印三个口径，全部透明给出，不做任何"重定义"：

| 口径 | 本设计实测 | 含义 |
|---|---|---|
| 最大绝对误差（占满量程 1.0） | 0.0112%  | `max|定点-浮点| / 满量程`，赛题「误差<0.1%」的标准口径 |
| 最大相对误差（相对信号峰值） | 0.0164%  | `max|定点-浮点| / 信号峰值`，误差占信号幅度的比例 |
| 逐点最大相对误差（含阻带近零） | 42.9%（不采用） | `max|定点-浮点| / |浮点|`，在阻带近零处被除零放大 |

为什么逐点相对误差会到 42%？阻带里信号被衰减到接近 0（如 `|浮点| = 0.001`），
此时哪怕只有 1 个 LSB（0.003%）的绝对误差，`0.003% / 0.001 = 300%`，纯粹是除近零数造成的假象，
不代表精度。所以赛题「误差 < 0.1%」的正确理解是误差相对信号量程（满量程或峰值）< 0.1%，
本设计 0.0112% 远达标。

> 关键结论：16bit Q1.15 的量化误差天然远小于 0.1%，赛题这条阈值对 16bit 定点是非常宽松的。

## 5. 文件格式（严格对应契约 D/E）

- `coeffs.vh`：82 行 `localparam signed [15:0] Hk = 16'sd<十进制>;`，`H0 = h[0]`（当前样本），`H81 = h[81]`（最老样本）。
- `coeffs.hex`：82 行，每行 4 位十六进制补码，`$readmemh` 读入 `coeff_mem[0:81]`。
- `stim.hex`：256 行输入样本（Q1.15）。
- `exp.hex`：337 行期望输出（定点参考，与 RTL 逐位一致）。
- `*.hex` 被 `.gitignore` 排除（不进 git），`coeffs.vh` 提交。

## 6. 使用方法

```powershell
# 一键生成全部文件（默认 82 抽头 / 截止 0.12 / 256 样本）
python fir/fir_coeff.py --taps 82 --cutoff 0.12 --nsamp 256

# 对比不同窗函数（阻带衰减不同）
python fir/fir_coeff.py --window hann
python fir/fir_coeff.py --window blackman

# 校验 RTL 导出的结果（组合验收时用）
python fir/fir_coeff.py --check got.hex
```

依赖：优先用 `scipy.signal.firwin`；没有 scipy 时回退到与它完全等价的纯标准库窗函数法，
因此只装标准库也能跑。改任何参数都要重跑脚本重新生成 `.hex`，不要手改。

## 7. 与 A/B 的接口约定

- A 的 `tb_fir_core.v`：`$readmemh` 读 `coeffs.hex` 逐拍写 `coef_we/coef_idx/coef_din`，读 `stim.hex` 喂 `din`，
  输出与 `exp.hex` 逐位比对（流水线延迟 5 拍，比对时对齐，契约 E.6）。
- B 的 `tb_fir.v`：经 AXI 写 `COEF[k]`（基址 `0x4000_0000 + 0x100 + 4k`）下发系数，期望值取自 `coeffs.hex`。
- 三者交叉核对：A 的 RTL 输出 == `exp.hex`，B 的 AXI 读回 == `exp.hex`。
