## 3. 一个重要的简化：三种"传输场景"不需要额外硬件

阶段目标里写「支持存储器↔FIR、存储器↔存储器、UART↔存储器」——
**这三种在硬件上是同一件事：把数据从 `SRC` 搬到 `DST`。**

差别只在**地址是否递增**：

| 场景 | SRC_INC | DST_INC |
|---|---|---|
| 存储器 → 存储器 | 1 | 1 |
| 存储器 → FIR 的 DIN 寄存器 | 1 | **0**（FIR 的 DIN 是固定地址，每次写一拍就喂一个样本） |
| FIR 的 DOUT → 存储器 | **0**（轮询读同一个地址） | 1 |
| UART → 存储器 | **0**（UART 的 RXDATA 是固定地址） | 1 |
| 存储器 → UART | 1 | **0**（UART 的 DATA 是固定地址） |

**所以引擎只要支持"源/目的地址各自可选递增"就够了，不需要为三种场景写三套逻辑。**
这正是 `CTRL` 的 bit1 / bit2 的用途。

## 4. 三人分工

### 👤 A —— DMA 配置通路与顶层集成

| 项 | 内容 |
|---|---|
| **新建文件** | `RTL/dma_regs.v`（AXI4 从口 + 24 个寄存器）、`RTL/dma.v`（顶层） |
| **分支** | `phase3-A-dma-top` |

**要做**

1. **`dma_regs.v`**：AXI4 从口（5 通道，带 ID），基址 `0x4000_1000`
   - 6 通道 × 4 寄存器 = 24 个，映射见 §2.1
   - 写 `CTRL[0]=1` 产生 `start` 脉冲给对应通道
   - 读 `CTRL`/`STATUS` 回状态
2. **`dma.v`** 顶层：
   - 实例化 1 个 `dma_regs` + **6 个 `dma_engine`**
   - **6 → 1 的 AXI4 主口仲裁**（round-robin，突发期间锁定，和阶段 2 互连同样的思路）
   - **中断生成**：`irq_done[5:0]`、`irq_err`
   - **预留链式传输**：参数 `CHAIN_EN`（默认 0）+ 挂钩注释，本阶段不实现

**验收**

- [ ] 24 个寄存器读写正确（用 C 的 TB 验）
- [ ] 单个通道跑通搬运
- [ ] **6 个通道同时启动**时仲裁正确（不能饿死任何一个）
- [ ] 中断：每个通道完成后 `irq_done` 对应位拉高
- [ ] 接 C 的 checker，**AXI 主口和从口都零违规**

**起点建议**：先用一个**空壳 `dma_engine`**（只回 `busy=0, done=0`）把顶层和仲裁写通，
等 B 的真引擎来了再替换 —— 这样**不用等 B**。

---

### 👤 B —— DMA 数据搬运引擎

| 项 | 内容 |
|---|---|
| **新建文件** | `RTL/dma_engine.v` |
| **分支** | `phase3-B-dma-engine` |

**要做**（接口严格按 §2.2 契约 B）

1. **单通道搬运**：从 `cfg_src` 读 `cfg_len` 个字 → 写到 `cfg_dst`
2. **AXI4 主口**（标准信号）：
   - **读突发**：AR/RLEN 用 INCR，RLAST 正确
   - **写突发**：AW/WLEN 用 INCR，WLAST 正确，WSTRB 全 1（整字传输）
   - 单拍（LEN=0）也是 INCR 的特例，不用单独写一套
3. **4KB 边界自动拆分**：`AWLEN/ARLEN` 最大 256 拍，且**一个突发不许跨 4KB**
   - 例如搬 1000 个字，要自动拆成若干段（每段不超过 4KB）
4. **地址递增可选**：`cfg_src_inc` / `cfg_dst_inc` 各自控制（见 §3）
5. **流控**：读回来的数据要能暂存，等写通道有空再发（建议用一个同步 FIFO，
   `RTL/sync_fifo.v` 已经有了可以直接例化）
6. **错误处理**：`BRESP/RRESP = SLVERR` → 停传输、拉高 `err`

**验收**

- [ ] 单拍搬运正确
- [ ] INCR 突发搬运正确（含超过 256 拍的长传输自动拆分）
- [ ] 跨 4KB 边界的传输被正确拆分（不能发一个跨界的突发）
- [ ] `SRC_INC=0` / `DST_INC=0` 时地址保持不变（模拟 UART/FIR 固定地址）
- [ ] 错误响应能让引擎停下来并报错
- [ ] 接 C 的 checker，**主口零违规**

> 💡 **起点建议**：引擎里"怎么发一个合法的 INCR 突发"这件事，
> 可以参考阶段 2 的 `RTL/axi_to_apb.v` 里怎么**接收**突发（反过来理解）。

### 👤 C —— DMA 验证（含中断用例）

| 项 | 内容 |
|---|---|
| **新建文件** | `TB/dma_slave_model.v`（AXI4 存储器模型）、`TB/tb_dma.v`（主测试台） |
| **分支** | `phase3-C-dma-tb` |

**要做**

1. **`dma_slave_model.v`**：一个简单的 **AXI4 从设备模型**（当存储器用）
   - 挂 64KB 存储（可以用数组）
   - 支持单拍 + INCR 突发、WSTRB、RLAST
   - **故意注入延迟**（可配置等待拍数），逼出 DMA 的流控问题
   - 这是 A 和 B 都能用的公共件
2. **`tb_dma.v`**：
   - **寄存器测试**：24 个寄存器逐个写读
   - **存储器 → 存储器**：单拍 + INCR 突发（含跨 4KB 的长传输）
   - **UART 场景**：`DST_INC=0`（固定地址）搬 N 个字，检查地址没变
   - **FIR 场景**：往固定地址写 N 个样本，检查顺序正确
   - **6 通道并发**：同时启动 6 个通道，检查仲裁不饿死、数据都不错
   - **中断用例**（交付里明确要求的）：
     - 每个通道完成后 `irq_done[N]` 单独拉高
     - 错误注入后 `irq_err` 拉高
     - 中断的**电平/脉冲形状**符合 `docs/任务四` 的定义
   - **挂 AXI 协议检查器**：在 DMA 的**从口**和**主口**各挂一个
     `axi_protocol_checker`（阶段 2 的成果），全程零违规才算过

**分工上的好处**：C 是**独立的验证者**，不写 RTL，因此能真正挑出 A 和 B 的问题
（自己测自己的代码容易漏）。

**验收**

- [ ] 上面每一类场景都有用例，且全部通过
- [ ] AXI 协议检查器在 DMA 主口 + 从口都是 **0 违规**
- [ ] 长时间随机激励下无死锁

## 5. 为什么这次也能三个人同时开工

靠**空壳**（和阶段 1 一样的办法）：

| 人 | 依赖谁 | 怎么先开工 |
|---|---|---|
| **A** | 需要 B 的 `dma_engine` | **先写一个空壳引擎**（端口齐全、行为为空），把顶层和仲裁跑通；B 的真引擎到了直接替换 |
| **B** | 谁都不依赖 | 引擎对外是**标准 AXI4 主口**，用 C 的从设备模型当对手就能单独测 |
| **C** | 需要接口，不需要实现 | 按 §2 的契约写 TB，**用空壳也能跑**（只是结果不对而已） |

**所以三个人第一天都能开工** ✔

## 7. 集成验收（三人各自完成后一起做）

三条分支合进 `main` 后：

```
CPU ──AXI从口──▶ dma_regs（A）
                      │ cfg
                      ▼
                 dma.v 顶层（A）
                 ┌────────────────────┐
                 │  6→1 AXI 仲裁      │
                 │  中断生成          │
                 └──┬──┬──┬──┬──┬──┬──┘
                    │  │  │  │  │  │
                  eng0 eng1 ... eng5   （B，每个对外是 AXI4 主口）
                    └──┴──┴──┴──┴──┴──┘
                            │ AXI4 主口（ID = {CH,1'b1}）
                            ▼
                     阶段 2 的 AXI 互连
```

**集成要测的场景**

- [ ] 6 通道各自单独搬运
- [ ] 6 通道**同时**搬运（仲裁）
- [ ] 存储器 → 固定地址（模拟 UART/FIR）
- [ ] 固定地址 → 存储器
- [ ] 中断：6 个 `irq_done` + 1 个 `irq_err`
- [ ] DMA 主口 + 从口，AXI checker 均 **0 违规**
- [ ] 接进阶段 2 的互连后，CPU 和 DMA 同时访问也不出错
