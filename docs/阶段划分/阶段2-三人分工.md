## 1. 为什么这次三个人能「完全不交织」

**关键原因：三个人的连接点全是标准 AXI4 接口，AXI 规范本身就是契约。**

| 人 | 他的模块对外暴露什么 | 需要和别人协商什么 |
|---|---|---|
| **A** | AXI4 **从口 ×2**、AXI4 **主口 ×5** | **什么都不用** |
| **B** | AHB-Lite **从口** + AXI4 **主口 ×1** | **什么都不用** |
| **C** | 挂在任意 AXI 端口上的监视器 | **什么都不用** |

**信号名、位宽、握手规则全部由 AXI 规范 + `docs/任务四` 定死，没有一句自定义信号需要三方开会定。**

> 这和阶段 1 不同 —— 阶段 1 需要冻结 `fir_core` 的自定义端口，
> 阶段 2 的三个模块之间**天然就是标准接口**，所以可以真正第一天就同时开工。

## 3. 三人分工

### 👤 A —— AXI 互连 + 仲裁（最难点）

| 项 | 内容 |
|---|---|
| **新建文件** | `RTL/axi_ic.v`（必要时拆出 `RTL/axi_arbiter.v` 作独立子模块） |
| **分支** | `phase2-A-interconnect` |

**要做**

1. **2 主 5 从交叉开关**，按 §2.2 的地址表做译码
   - 从口：`s0_axi_*`（CPU/桥）、`s1_axi_*`（DMA）
   - 主口：`m0`（FIR）、`m1`（DMA 配置）、`m2`（SRAM）、`m3`（ROM）、`m4`（AXI→APB）
2. **5 个通道各自独立仲裁**（AW / W / B / AR / R）
   - 用 **round-robin**，不要固定优先级（否则一个主会被饿死）
   - ⚠️ **写数据通道必须跟随 AW 通道的授权** —— 这是最容易写错的地方：
     AW 授权给主 0，那么接下来的 W 拍必须也走主 0，否则从设备收到的数据是错乱的
3. **Burst 锁定**：一个突发期间不换授权（直到 WLAST / RLAST）
4. **无死锁**：保证依赖是单向的（主 → 从），不引入任何"从等主"的回路

**验收**

- [ ] 两个主同时发起时，仲裁正确轮转（不能饿死任一方）
- [ ] 单拍（LEN=0）与 INCR 突发都通
- [ ] **每个从设备都能被两个主正确访问**（5×2 = 10 条路径全测）
- [ ] 长时间随机激励下无死锁
- [ ] 接上 C 的 checker，**零协议违规**

---

### 👤 B —— AHB→AXI 桥

| 项 | 内容 |
|---|---|
| **新建文件** | `RTL/ahb2axi.v` |
| **参考起点** | `RTL/cpu/cortexm0ds/ahb2axi4_*.v`（赛题包自带，可读、可改造，但对外接口要满足 `docs/任务四` 1.2 节） |
| **分支** | `phase2-B-ahb2axi` |

**要做**

1. **AHB-Lite 从口**（解 `docs/任务四` 0.4 节）：
   `HADDR / HTRANS / HWRITE / HSIZE / HBURST / HPROT / HWDATA`（入）
   `HRDATA / HREADY / HRESP`（出）＋ `HSEL`
2. **AXI4 主口**，**固定 ID=0**（`docs/任务四` 1.3 节：CPU 侧主设备 ID=0）
3. **5 拍流水**：把 AHB 的「地址期 → 数据期」翻译成 AXI 的 AW/W 分离握手
4. **HSIZE 对齐**（本模块最容易错的地方）：

   | `HSIZE` | 传输 | `WSTRB` 有效位 | 地址约束 |
   |---|---|---|---|
   | 3'b000 | 字节 | 1 位 | 任意 |
   | 3'b001 | 半字 | 2 位 | 地址 bit0 = 0 |
   | 3'b010 | 字 | 4 位 | 地址 bit[1:0] = 0 |

   **写**：数据要放到正确的字节 lane，`WSTRB` 只在对应位拉高
   **读**：从 `RDATA` 的正确 lane 取数据
5. **AHB 突发 → AXI INCR 突发**，地址按 SIZE 递增
6. **错误响应贯通**：AXI `BRESP/RRESP = SLVERR` → AHB `HRESP = ERROR`

**验收**

- [ ] 三种 `HSIZE` 的读写在**正确的 lane**（专门写用例测字节/半字）
- [ ] 非对齐地址的预期行为
- [ ] 连续 INCR 传输，地址递增正确
- [ ] 错误响应能贯通（AXI SLVERR → AHB ERROR）
- [ ] 接上 C 的 checker，零协议违规

### 👤 C —— AXI 协议 checker + 验证基础设施

| 项 | 内容 |
|---|---|
| **新建文件** | `TB/axi_protocol_checker.v` |
| **分支** | `phase2-C-checker` |

**要做**：一个**可参数化、可插拔**的 AXI4 协议检查器。
例化在任意 AXI 端口上（主口或从口），自动监测并报表。

| # | 检查项 | 依据 |
|---|---|---|
| 1 | `VALID` 拉高后**不许撤销**（直到握手完成） | AXI 规范 A3.2.1 |
| 2 | `VALID` **不许等 `READY`**（通道依赖铁律，写错会死锁） | A3.2.1 |
| 3 | `WLAST` 必须恰好出现在最后一拍，且只能出现在 W 通道 | A3.1.2 |
| 4 | `RLAST` 同理（R 通道） | A3.1.2 |
| 5 | `AWLEN/ARLEN` 与实际 W/R 拍数**一致** | A3.4.1 |
| 6 | INCR 模式地址按 `SIZE` 递增**正确** | A3.4.1 |
| 7 | 突发**不跨 4KB 边界** | A3.4.1 |
| 8 | 写响应 `BID` 的顺序与 `AWID` **一致** | A5.3 |
| 9 | 复位期间**不许有 `VALID` 拉高** | A3.1.1 |

**输出**：每个被监测端口一个 `error_count`，任何违规立刻 `$display` 报出（带时间戳和通道名）。

**C 额外负责**：给**已有的 `RTL/axi_to_apb.v`** 接上 checker 复验一遍
（它已过 19 项功能检查，但**没有按 AXI 规范逐条扫过**）。

**验收**

- [ ] **checker 自己能通过"故意违规"的自测** —— 喂它一段错误波形，必须报错。
      （否则无法证明它不是个摆设）
- [ ] 被 A 和 B **直接例化使用**，且不产生误报
- [ ] `RTL/axi_to_apb.v` 接上 checker 后零违规

> 💡 **C 的价值**：checker 是 A 和 B 的**公共裁判**。
> C 先花半天写出最小可用版（哪怕只有第 1、2、3 条），两个人立刻就能用上。
> **不要等做完美再给**。

而阶段 1 用了 1.5 周，**阶段 3、4 还没算**。整体计划已经严重超期。

### 按「分数密度」砍的建议

| 优先级 | 做什么 | 理由 |
|---|---|---|
| 🔴 **必做** | **AXI 互连 + 仲裁** | 初赛「AXI 协议合规 15 分」的核心；没有它整个 SoC 串不起来 |
| 🟠 **强烈建议** | **协议 checker（简化版）** | 直接支撑评分原文「单拍与 Burst 传输均无协议错误；无死锁」 |
| 🟡 **建议先不做** | **自己重写 AHB→AXI 桥** | 赛题包自带的那套已在用，**先把 6 天省给互连** |

**结论与当前安排**：

- **A（互连+仲裁）和 C（checker）立刻开工** —— 这两块是分数密度最高的。
- **B 的情况看队友进度**：如果 B 在阶段 1 已经完工（**目前就是这种情况**——
  `RTL/fir.v` 已合并进 main），B **可以直接开工**做 AHB→AXI 桥，不用等。
  如果 B 还在忙阶段 1，就先让 A 和 C 两个人推进。
- 万一 B 有空但互连那边卡住了，**让 B 去支援 A 的验证**（互连的验证工作量比写代码还大）。

## 5. 集成验收（三人各自完成后一起做）

三条分支合进 `main` 后：

```
        Cortex-M0
            │ AHB-Lite
     ┌──────▼──────┐
     │  AHB→AXI 桥  │  ← B（或赛题包自带）
     └──────┬──────┘
            │ AXI4 (ID=0)              ┌─ DMA 数据口 (ID=1)
     ┌──────▼──────────────────────────▼──────┐
     │        AXI 互连 + 仲裁（A）             │
     └──┬────┬────┬────┬────┬─────────────────┘
        │    │    │    │    │
       FIR  DMA  SRAM ROM  AXI→APB 桥 ✅
       配置                   │ APB
                              └─ UART ✅
```

**集成要测的场景**

- [ ] CPU 单独访问全部 5 个从设备
- [ ] DMA 单独访问全部 5 个从设备
- [ ] **CPU 和 DMA 同时访问同一个从设备**（仲裁）
- [ ] **CPU 和 DMA 同时访问不同从设备**（并行，crossbar 的意义）
- [ ] 全程接 checker，**零协议违规**
- [ ] 长时间（几万拍）随机激励，**无死锁**
