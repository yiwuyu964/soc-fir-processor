## 2. 接口速查（都已被契约冻结，照抄即可）

### 2.1 契约 A：`dma_regs` → 顶层的配置总线（5 条展平向量）

```verilog
output wire [6*32-1:0] cfg_src;    // 每通道源地址，ch 占 [ch*32 +: 32]
output wire [6*32-1:0] cfg_dst;    // 每通道目的地址
output wire [6*32-1:0] cfg_len;    // 每通道传输字数（32bit 字个数）
output wire [6*32-1:0] cfg_ctrl;   // bit0 START(脉冲) / bit1 SRC_INC / bit2 DST_INC
input  wire [6*32-1:0] st_status;  // bit0 BUSY / bit1 DONE / bit2 ERR
```

### 2.2 寄存器映射（任务三 4.2，每通道 16 字节）

| 偏移 | 名称 | 访问 | 说明 |
|---|---|---|---|
| `0x00+0x10·N` | SRC | W | 源地址 |
| `0x04+0x10·N` | DST | W | 目的地址 |
| `0x08+0x10·N` | LEN | W | 传输字数 |
| `0x0C+0x10·N` | CTRL | W/R | 写 bit0 START(自清)/bit1 SRC_INC/bit2 DST_INC；读 bit29 ERR/bit30 BUSY/bit31 DONE |

解码：`channel = addr[6:4]`，`reg_type = addr[3:2]`（0=SRC,1=DST,2=LEN,3=CTRL）。

### 2.3 中断（任务四 1.6，电平）

```verilog
output wire [5:0] irq_done;  // irq_done[ch] = 引擎 status[1]（DONE，粘滞到下次 start）
output wire       irq_err;   // = 6 通道 status[2]（ERR）的或
```

### 2.4 AXI ID（契约 C）

```verilog
m_axi_awid = m_axi_arid = { CH[2:0], 1'b1 }   // ID[0]=1 是 DMA 标记，ID[3:1]=CH
```

## 3. 已想清楚的关键设计点

### 3.1 `dma_regs`（AXI 从口）

- FSM：`S_IDLE → S_GETW → S_BRESP / S_RBEAT → S_IDLE`，单拍 + INCR 突发都支持。
- 写区域预检：整笔突发任一拍落到非法区 → 整笔 SLVERR 且无副作用（写使能由 `w_err` 门控）。
- START 一拍脉冲：CPU 写 CTRL[0]=1 的下一拍，`cfg_ctrl[ch][0]` 产一拍高电平，其余恒 0；START 位自清（读回恒 0）。
  实现：`start_pulse` 每拍默认清 0，S_GETW 里写 CTRL 且 bit0=1 时置 1。
- CTRL 读回：`{ st_status[ch][1]/*DONE→31*/, st_status[ch][0]/*BUSY→30*/, st_status[ch][2]/*ERR→29*/, 26'd0, inc_r[ch][1]/*DST_INC→2*/, inc_r[ch][0]/*SRC_INC→1*/, 1'b0 }`。
- 只读限制：读只有 CTRL 合法（r_type==3），读 SRC/DST/LEN → SLVERR。

### 3.2 `dma` 顶层（6→1 仲裁 + 中断）

- 写通道：AW 用 `axi_arbiter #(.N(6))` 做 round-robin，`aw_req[g] = eng_awvalid[g] && !w_active`；AW 握手后 `w_active=1, w_owner=授权引擎`；W 跟随 `w_owner`；`w_last` 握手后 `w_active=0`。突发期间锁定到 WLAST。
- B 回选：`eng_bvalid[g] = m_axi_bvalid && (m_axi_bid[3:1] == g)`，`m_axi_bready = eng_bready[m_axi_bid[3:1]]`。
- 读通道：AR 同理 round-robin，`ar_req[g] = eng_arvalid[g] && !r_active`，锁定到 RLAST；R 按 `m_axi_rid[3:1]` 回选。
- AW/AR 一热 mux：6 引擎 → 共享主口，用 `({W{aw_grant[g]}} & eng_sig[g])` 的 6 项或。
- AWREADY/ARREADY 回选：`eng_awready[g] = aw_grant[g] & m_axi_awready`（同样 AR）。
- 状态聚合：`st_status[ch*32 +: 32] = 引擎 status`（引擎 status 已是 bit0 BUSY/bit1 DONE/bit2 ERR）。
- 链式传输：`parameter CHAIN_EN = 0` 预留，本阶段不实现（端口留注释钩子即可）。

## 4. 提示点（易错 / 必须记住）

1. START 是一拍脉冲，不是电平。别在顶层再做边沿检测 —— `cfg_ctrl[ch][0]` 已经是 `dma_regs` 生成好的脉冲，直接接引擎的 `start`。
2. `LEN=0` 语义 = 传 0 个字（不是 AXI 的 `AWLEN=0`=1 拍）。引擎已按此实现，寄存器层直接透传即可，别换算。
3. CTRL 读回要映射，不是直接回 `inc_r`：DONE/BUSY/ERR 来自 `st_status`，不是 CTRL 寄存器本身。
4. 6→1 仲裁要「突发期间锁定」：AW 锁到 WLAST、AR 锁到 RLAST，否则第二个引擎的写数据会插进第一个引擎的突发里（与阶段 2 互连同思路）。
5. B/R 回选用 ID 的 `[3:1]` 字段（=CH），不是 `[0]`（`[0]` 恒 1 是 DMA 标记，区分不了 6 个通道）。
6. `start_pulse` 只能在一个 always 块里驱动（默认清 0 + 写 CTRL 时置 1），否则多重驱动。踩过这个坑。
7. `m_axi_bready` 只赋一次：`= eng_bready[m_axi_bid[3:1]]`，别再加一个或约减的重复赋值。踩过这个坑。
8. **TB 里不能过程赋值 DUT 的 `m_axi_*` 输出**（那是 DUT 驱动的 wire）；要给数据口预置初值得另起一路 AXI 主 BFM。
9. 数据口挂互连 `s1`（主 ID=1）：引擎 ID 已是 `{CH,1'b1}`，互连靠 `ID[0]` 区分 CPU/DMA，顶层仲裁时 ID 原样透传，不许改写。
10. 写完先 `-Wall` 编译 + 跑自测再提交：`iverilog -g2012 -Wall` 要零告警；C 的 `tb_dma.v` 会挂 `axi_protocol_checker` 主口/从口，全程零违规才算过。

## 5. 验证建议（自测最小集）

1. 配置口写 4 个寄存器 → 读回 CTRL 校验 bit31 DONE / bit30 BUSY / bit29 ERR / bit2/1 保持。
2. 写 CTRL[0]=1 → 观察到 `cfg_ctrl[0][0]` 产一拍脉冲（其余拍恒 0）。
3. 单通道 SRAM→SRAM 搬 4 字 → 轮询 CTRL 等 DONE → 查 `irq_done[0]=1`、`irq_err=0`。
4. 6 通道同时启动 → 逐通道 DONE 都置位、`irq_done[5:0]` 全 1、无饿死。
5. 挂 C 的 `axi_protocol_checker`（主口 SIDE=1、从口 SIDE=0），全程 0 违规。

> 完整逐位数据比对由 C 的 `TB/tb_dma.v` 负责，A 的自测只需验「配置通路 + 搬运完成 + 中断」。
