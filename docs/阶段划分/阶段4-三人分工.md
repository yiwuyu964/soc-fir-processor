## 二、先冻结顶层端口

### 2.1 契约 S：`soc_top` 的对外端口

```verilog
module soc_top #(
    parameter ADDR_W     = 32,
    parameter DATA_W     = 32,
    parameter ID_W       = 4,
    parameter SRAM_BYTES = 65536,       // 片内 SRAM 大小（64KB）
    parameter CLK_FREQ   = 100_000_000, // 时钟频率，给 UART 算波特率
    parameter UART_DIV   = 10           // BAUD = CLK_FREQ / UART_DIV
)(
    input  wire clk,        // 单一时钟域（仿真 100MHz，综合目标 50MHz）
    input  wire rst_n,      // 低有效异步复位
    output wire uart_txd,
    input  wire uart_rxd
);
```

这是本阶段唯一需要开会定的东西，C 的 `tb_soc.v` 要按它例化。

`UART_DIV` 到 UART 的换算要留神：`RTL/uart_apb.v` 的参数是 `CLK_FREQ` 和 `BAUD`，不是分频系数，所以 `soc_top` 内部得自己算——`uart_apb #(.CLK_FREQ(CLK_FREQ), .BAUD(CLK_FREQ / UART_DIV))`。举例：`CLK_FREQ=100MHz`、`UART_DIV=868` 得到 115200 的标准波特率；仿真想跑快就把 `UART_DIV` 调小。

SWD 调试口这块没什么要处理的。核对过 `RTL/cpu/cortexm0ds/`，这个 IP 不暴露 SWDIO/SWCLK，所以顶层没有需要固定电平的调试脚。早期版本这里写了一句"在顶层固定电平"，是多余的。

### 2.2 决策 D1：ROM Boot 做不做

阶段 4 原文写的是"可选 ROM Boot"，两条路：

| 方案 | 地址映射 | 代价 |
|---|---|---|
| A（规范） | ROM @`0x0000_0000` 放固件，SRAM @`0x2000_0000` | 多写一个 `axi_rom.v`，还要解决固件怎么装进 ROM |
| B（初赛） | SRAM @`0x0000_0000`，程序、数据、栈共用 64KB，不做 ROM | 省一个模块、省半天调试 |

选了 B。理由是 M0 复位后从 `0x0` 取向量表和入口，只要 `0x0` 有可读存储器就能启动；初赛不考查 ROM/SRAM 分区，报告里注明"初赛简化处理"就够。

这个决定直接决定 SRAM 挂在哪个主口，所以必须第一天定下来。

### 2.3 地址映射（按方案 B）

| 基地址 | 大小 | 模块 | 互连主口 |
|---|---|---|---|
| `0x0000_0000` | 64KB | 片内 SRAM（程序+数据+栈） | **m3** |
| `0x4000_0000` | 4KB | FIR | m0 |
| `0x4000_1000` | 4KB | DMA 配置口 | m1 |
| `0x4000_2000` | 64KB | AXI→APB 桥（内含 UART） | m4 |
| ~~`0x2000_0000`~~ | — | 方案 B 不用，m2 留空 | — |

**m2 和 m3 千万别弄反，这是本阶段最容易出错的地方。** `axi_ic.v` 的译码函数 `f_decode` 里写的是 `a[31:16]==16'h0000 → 3'd3`（走 m3）、`a[31:16]==16'h2000 → 3'd2`（走 m2）。互连的主口编号与地址表的行序不是一回事，`0x0` 这一段落在 m3。

所以方案 B 的 SRAM 必须接 `m3_axi_*`，`BASE_ADDR` 用默认值 0。要是接到 m2，SRAM 的实际地址就变成 `0x2000_0000`，而 CPU 复位从 `0x0` 取向量表时会打到悬空的 m3 上，结果是 DECERR，SoC 起不来。

m2 留空的时候要接静态无效值（`awready`/`wready`/`bvalid`/`rvalid` 拉 0），别让它悬空。

主设备的 AXI ID：CPU 经 AHB→AXI 桥为 0，DMA 为 `{CH[2:0], 1'b1}`。

## 三、三人分工

### A —— SoC 顶层集成

新建 `RTL/soc_top.v`，分支 `phase4-A-soc-top`。要做的是按上面的地址映射把九个模块连起来：

```
cortexm0ds_logic（RTL/cpu/cortexm0ds/cortexm0ds_logic.v）   ← AHB-Lite 核
      │ AHB-Lite
ahb2axi（RTL/ahb2axi.v）                     ← 主设备 ID = 0
      │ AXI4
axi_ic（RTL/axi_ic.v）+ axi_arbiter
   ├─ m0 → fir（RTL/fir.v）            @0x4000_0000
   ├─ m1 → dma（RTL/dma.v）            @0x4000_1000
   ├─ m3 → axi_sram（RTL/axi_sram.v）  @0x0000_0000   ← 是 m3，不是 m2
   ├─ m2 → 不用，接静态无效值
   └─ m4 → axi_to_apb（RTL/axi_to_apb.v）
                │ APB
                └─ uart_apb @0x4000_2000
```

**CPU 用哪个文件必须写死，早期版本这里含糊过。** `RTL/cpu/cortexm0ds/` 下有两个都能当 CPU 的模块，接口完全不同：

`cortexm0ds_logic.v` 是纯 AHB-Lite 核，端口是 `haddr_o`/`htrans_o`/`hwrite_o` 这套输出加 `hrdata_i`/`hready_i`/`hresp_i` 反向输入。本设计用的是它，经我们自己的 `ahb2axi.v` 转成带 ID=0 的 AXI4——这条链路在阶段 2 单独验过。

`cortexm0ds.v` 内部已经例化了 ARM 自带的 `ahb2axi4_if`，对外直接是 AXI4，而且没有 ID 信号。用它的话我们写的 `ahb2axi.v` 完全用不上，还得在顶层把互连从口的 ID 输入硬绑成 0。所以不采用。

其余三件事：统一时钟复位（全片单时钟域，复位同步释放）；中断连线（FIR 的 `irq_done`→IRQ0、`irq_err`→IRQ1，DMA 的 `irq_done[5:0]`→IRQ2~7、`irq_err`→IRQ8）；把 `UART_DIV` 换算成 `uart_apb` 的 `CLK_FREQ`/`BAUD`。

验收：整个 SoC 能 `iverilog -g2012 -Wall` 零告警编译；冒烟能读写 SRAM、能读 FIR 的 STATUS；地址映射与上表逐条一致。

为了避免等 B 的 SRAM，先用空壳 SRAM（端口齐全、读返回 0）把顶层连起来跑通，真 SRAM 到了直接替换。这个办法实际用上了，省了至少半天。

实际结果：`tb_soc` 13 项检查全过，UART 回显闭环正常。

### B —— 片内 SRAM

新建 `RTL/axi_sram.v` 和 `TB/tb_axi_sram.v`，分支 `phase4-B-axi-sram`。这项在阶段 4 开工时已经完成并合入 main，下面保留原任务描述，作为验收依据。

要做的是 AXI4 从口（5 通道带 ID），`SRAM_BYTES` 参数化（默认 64KB）；支持单拍和 INCR 突发、`WSTRB` 字节选通、`RLAST` 按拍数对齐；**必须可综合**，不能用 `TB/axi_mem_model.v` 那种纯仿真写法；地址越界返回 `DECERR`；配自己的单元测试台。

验收：单拍与 INCR 读写正确、`WSTRB` 只改选中的字节、挂协议检查器零违规、`-Wall` 零告警。

起步时参考了 `TB/axi_mem_model.v` 的结构，但那是仿真模型，必须改写成可综合版本——这个改写不是加几行那么简单，行为模型的时序假设和可综合实现不同，基本等于重写。

实际结果：`tb_axi_sram` 47 项检查全过。

### C —— 启动代码 + C 驱动 + 顶层验证

新建 `sw/`（`startup.s`、`linker.ld`、`main.c`、`build.py`）和 `TB/tb_soc.v`，分支 `phase4-C-soc-tb`。

启动代码要写向量表（初始栈指针加复位入口），从 `0x0` 启动；链接脚本按第二节的地址映射。这里有个 Cortex-M0 的细节：它的向量表第一项是初始 SP，第二项是复位向量，HardFault 在第三项。SP 必须在链接脚本里指向 SRAM 顶部，否则第一条 `push` 就会写飞。

固件核心是 UART 回显：从 UART 收一个字节，原样发回去。顺便做冒烟——读 FIR 的 STATUS、读写 SRAM、读写 DMA 寄存器。

编译脚本 `sw/build.py` 调 `arm-none-eabi-gcc` 出 `.hex`。工具链路径必须自动探测，不能硬编码。另外 `firmware.hex` 是被 gitignore 忽略的构建产物，**每次跑测试前要重新编译**，用旧文件会出很诡异的问题——这一点在后面排查过一个真实故障：`firmware.hex` 是坏的，`main` 字面量池里的一个常量被写成了 `0x696C0200` 而不是 `0x00000200`（多出来的两个字节正好是 ASCII 的 "li"），CPU 取到非法地址直接进 HardFault。现象是 CPU 停在 `Default_Handler`，看起来像 RTL 有 bug，实际是构建产物过期。后来 `sim/sim.ps1` 里加了一步自动重建固件，堵住这个坑。

顶层测试台 `tb_soc.v` 要例化 `soc_top`、驱动时钟复位、用 `$readmemh` 把固件装进 SRAM（层次化引用或后门）、模拟 PC 端串口给 `uart_rxd` 发一串字节并检查 `uart_txd` 原样回显、内部 AXI 端口挂协议检查器。

验收：冒烟读写各外设寄存器正确、UART 回显发 N 个字节全部原样回来、内部检查器零违规、写出回显记录。

关于"回显记录"这件事：原本计划单独写一份 `docs/阶段4-UART回显记录.md`，最后没有单独成文——回显的通过判据直接固化在 `tb_soc` 的 13 项检查里，每次跑仿真都会重新验证一遍，比一份静态的日志截图更可靠。

## 四、为什么这次也能三个人同时开工

靠空壳加冻结的顶层端口：

| 人 | 依赖谁 | 怎么先开工 |
|---|---|---|
| A | B 的 `axi_sram.v` | 已到货；万一没合上就用空壳 SRAM 占位，读返回 0 |
| B | 谁都不依赖 | 已完成。注意测 AXI 从设备要配 AXI 主 BFM，`axi_mem_model` 是从设备模型，不能当主设备用 |
| C | A 的顶层、B 的 SRAM | 测试台按契约 S 的端口写；`sw/` 的启动代码和驱动现在就能写，地址映射已冻结 |

C 先写 `sw/`，B 写 SRAM，A 写顶层，三条线并行推进。

## 五、集成顺序

```
第 1 天  三人一起定契约 S 和决策 D1                    ← 十分钟
第 1-3 天 A 写 soc_top（空壳 SRAM）  B 写 axi_sram  C 写 sw/
第 3 天  B 的 SRAM 合进 A 的顶层 → 第一次冒烟（CPU 能读写 SRAM）
第 4 天  C 的 tb_soc 跑起来 → 冒烟测试
第 5 天  UART 回显跑通                                ← 本阶段核心交付
第 6 天  挂检查器全面扫 + 整理回显记录
第 7 天  缓冲 / 补漏
```

计划约一周。当时截止日是 10 月 19 日，阶段 1~3 已经花掉大部分时间，所以做了两个取舍：ROM Boot 不做（省半天到一天）；冒烟测试简化成"读 FIR STATUS 得到合理值 + 读写 SRAM 正确"。

## 七、上一轮 review 的遗留项

阶段 3 交付后队友提了四条意见，全部成立且已修：

| # | 问题 | 修法 |
|---|---|---|
| 1 | `tb_dma.v` 把 DMA 直连存储器模型，绕过了 `axi_ic`，地址译码和 ID 回选那条链没被验证 | 新增 `TB/tb_dma_ic.v` 补集成用例 |
| 2 | 两个协议检查器都设了 `ALLOW_WRAP(1)`，把 WRAP 不支持的检查关掉了 | 改回默认 |
| 3 | 配置口 BFM 不校验 `BRESP`/`RRESP` | 新增 `TB/tb_dma_self.v` 补断言 |
| 4 | `dma_regs.v` 的读数据是组合逻辑、依赖实时 `st_status`，被背压时可能抖动 | 重构为寄存器输出 |

这一轮 review 的教训值得写进技术报告：**"我测过了"不等于"测全了"**。单模块测试通过，不代表它在真实拓扑里也通过，集成路径必须单独验证。第 1 条就是典型的例子——DMA 自己的测试台全过，但它根本没经过互连的译码和 ID 回选逻辑，而那条路径恰恰是阶段 2 花了最多精力做的部分。
