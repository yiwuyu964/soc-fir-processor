## 二、先冻结接口，再动手

这是全部分工的前提。冻结之后谁都不许私改，改了要三个人一起返工。

### 2.1 契约 A：`fir_core` 的数据通路端口

```verilog
module fir_core #(
    parameter DW   = 16,        // 数据位宽 Q1.15
    parameter CW   = 16,        // 系数位宽 Q1.15
    parameter AW   = 40,        // 累加器位宽（下限 38，取 40）
    parameter NTAP = 82         // 抽头数（81 阶 = 82 抽头）
)(
    input  wire                    clk,
    input  wire                    rst_n,
    input  wire                    flush,       // 清空延迟线与流水线（系数保留）
    input  wire                    en,          // 每拍处理一个样本
    input  wire signed [DW-1:0]    din,
    output wire signed [DW-1:0]    dout,
    output wire                    dout_v,      // dout 有效标志
    input  wire [$clog2(NTAP)-1:0] coef_idx,    // 系数写口
    input  wire signed [CW-1:0]    coef_din,
    input  wire                    coef_we
);
```

这里有个容易混的地方：`NTAP` 是 82 而不是 81。赛题说的"81 阶"是多项式阶数，实现在工程上需要 82 个系数和 81 个延迟单元。开工时写成 81，后来统一改成 82，接口约定不变。

### 2.2 契约 B：`fir` 顶层对外端口

按 `../任务4-模块接口信号清单.md` 1.5 节，不许改：AXI4 从口、5 通道、带 ID（`ID_W=4`）；`irq_done` 接 IRQ0（滤波完成，电平，读 STATUS 清除）；`irq_err` 接 IRQ1（溢出或读空）；基址 `0x4000_0000`。

### 2.3 契约 C：寄存器映射

按 `../任务3-地址映射与中断分配.md` 4.1 节：

| 偏移 | 名称 | 访问 | 说明 |
|---|---|---|---|
| `0x000` | CTRL | W | bit0 = 1 清空延迟线 |
| `0x004` | DIN | W | 写一个样本（16bit Q1.15） |
| `0x008` | DOUT | R | 读一个滤波结果（读即弹出） |
| `0x00C` | STATUS | R | [0] empty / [1] full / [2] done / [3] err / [31:16] FIFO 计数 |
| `0x100 + 4k` | COEF[k] | W | 第 k 个系数，k 取 0..81，占 0x100~0x244 |

开工时 STATUS 只定义了 FIFO 的 empty/full 两位，但 `任务4` 要求 `irq_done` 是"读 STATUS 清除"的电平信号，得有个 done 位才能配合。这个缺口当时标成了待确认项，由 B 去找写 `任务3` 的人补。后来补齐了，就是上表里的 [2] done 和 [3] err。

### 2.4 契约 D：系数文件格式

`coeffs.vh` 是给 Verilog 编译期用的：

```verilog
localparam signed [15:0] H0 = 16'sd20;
```

`coeffs.hex` 是给 `$readmemh` 用的，每行 4 位十六进制补码（`0014`、`FFEC` 这样）。

## 三、三人分工

### A —— FIR 数据通路

新建 `RTL/fir_core.v` 和 `TB/tb_fir_core.v`，分支 `phase1-A-core`。

要做的事：81 级延迟链加全并行乘法（82 个 16×16）；累加用 7 级加法树（82→41→21→11→6→3→2→1）而不是串行链；加法树分 3 段打拍，总共 5 级流水，吞吐仍是 1 sample/cycle；输出右移 15 位回 Q1.15 并做饱和。

验收标准是五条：流水线延迟恰好 5 拍、`flush` 后延迟线与流水线彻底清空、全量样本与黄金模型逐位一致、端口严格等于契约 A、`-Wall` 编译零告警。

实际结果：`tb_fir_core` 比对 337 个样本逐位一致；`tb_fir_core_contract` 的 8 项契约自检全过。

关于起点，当时考虑过拿 `fir_soc/rtl/fir_cfg.v` 里那版流水线实现当底子（延迟 5 拍、336 样本逐位一致），端口按契约 A 调整后放到 `RTL/`。后来是重写的，因为原型里还带着一堆与本阶段无关的东西，改比写慢。

### B —— FIR 的 AXI4 从接口与中断

新建 `RTL/fir.v` 和 `TB/tb_fir.v`，分支 `phase1-B-axi`。

关键在于这是 AXI4 从口而不是 AXI-Lite。要处理 `AWID/ARID` 到 `BID/RID` 的透传、`AWLEN/ARLEN` 与 `WLAST/RLAST`、`WSTRB` 写选通；单拍（LEN=0）和 INCR 突发都要支持，突发不跨 4KB；握手必须守住 VALID/READY 铁律——VALID 拉高后不许等 READY，通道之间不许有组合环。

寄存器映射严格按契约 C。系数通过 AXI 写 `COEF[k]`，经 `coef_we/coef_idx/coef_din` 下发到 `fir_core`；样本写 `DIN` 触发 `en` 一拍；结果从 `fir_core` 的 `dout/dout_v` 进入输出 FIFO，AXI 读 `DOUT` 时弹出。

输出 FIFO 深度定在 512，这个数字不是随手定的：DMA 一次搬运最多 338 个样本，留足余量避免反压，同时面积上只占一个 BRAM。

验收：单拍读写全过、INCR 写突发与读突发（含 RLAST）全过、突发期间零协议违规、对外端口等于 `任务4` 1.5 节、寄存器地址等于契约 C。

实际结果：`tb_fir` 通过，定点逐位一致、浮点 RRMSE < 0.1%；`tb_fir_asymmetric` 进一步覆盖了末抽头冲激、任意非对称系数、在线改系数和 flush。

### C —— 系数设计与黄金模型

新建 `fir/fir_coeff.py`，生成 `coeffs.vh`、`coeffs.hex`、`stim.hex`、`exp.hex`，配套说明写在 `../系数与黄金模型说明.md`。分支 `phase1-C-coeff`。

要做的事：设计线性相位低通滤波器（窗函数法，等价 `scipy.signal.firwin`），归一化到直流增益 1.0 并检查 `Σh ≈ 32768`；Q1.15 量化后按契约 D 输出；黄金模型同时给出定点参考（与 RTL 逐位一致）和浮点参考（真实数学答案）；算最大绝对误差和最大相对误差，对照赛题 0.1% 的要求；生成激励与期望输出供 A、B 的测试台直接 `$readmemh`。

验收：一条命令生成全部文件、增益归一化正确、误差报告 < 0.1%、格式严格等于契约 D、脚本只依赖标准库加 numpy/scipy 且缺依赖时给出清晰报错。

实际结果：脚本落在 `fir/fir_coeff.py`，默认 82 抽头、截止 0.12、256 样本。它同时被 `sim/sim.ps1` 调用——每次跑仿真都会把向量重新生成到临时目录，避免用上一次残留的旧数据。

```powershell
python fir\fir_coeff.py --taps 82 --cutoff 0.12 --nsamp 256

# 2) FIR 数据通路单元测试
# TB 从 fir/ 读 coeffs.hex / stim.hex / exp.hex，用 -g2012 编译

# 3) FIR AXI 接口单元测试
# 单拍 + INCR 读写突发 + 中断

# 4) 交叉核对
# A 的 RTL 输出与 C 的 exp.hex 逐位一致
# B 的 AXI 读回与 C 的 exp.hex 逐位一致
```
