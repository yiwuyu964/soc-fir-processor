# 任务三：地址映射表 + 中断向量分配

> 本文件是**接口契约的第一张表**：所有模块（Verilog 地址常量、C 头文件、测试台）都以此为准，
> 谁改谁负责通知全队。标 ✅ 的是**现有工程已经实现**的，标 ⬜ 的是**规范/待实现**的。

---

## 0. 一句话原则

> 地址：**4KB 对齐、大小取 2 的幂、互不重叠、按功能分组、按访问频率排先后、留扩展空档**。
> 中断：**异常号 0~15 系统保留；完成中断在前、错误中断在后；同模块连续；留空档**。

---

## 1. 设计约束（从赛题要求提炼，逐条落实）

| # | 约束 | 本设计的落实 |
|---|---|---|
| 1 | 遵循 Cortex-M0（ARMv6-M）预定义地址区域 | 第 2 节分区表 |
| 2 | AXI 从设备地址 4KB 对齐，大小是 4KB 的整数倍 | 所有外设基址都是 0x…_0000，大小 4KB 起步 |
| 3 | 各外设地址范围不重叠 | 第 4 节每个区间互不覆盖 |
| 4 | 按功能类型分组 | 高速 AXI 一组、慢速 APB 一组 |
| 5 | 按访问频率排优先级（近、热、宽） | FIR（最热）→ DMA → APB 慢速 |
| 6 | 预留扩展空间 | 外设区后半段 + APB 内部都留了空档 |
| 7 | 大小取 2 的幂 | 4KB=2¹²、64KB=2¹⁶ |
| 8 | 异常号 0~15 保留，最多 32 个外设中断 | 只用 IRQ0~12，留 IRQ13~31 |
| 9 | 完成中断优先于错误中断 | FIR/DMA 的 done 号都 < 它的 error 号 |
| 10 | 同模块中断号连续 | DMA 通道 0~5 = IRQ2~7 连续 |

## 2. Cortex-M0 预定义地址区域（架构前提，先背这张）

ARMv6-M（Cortex-M0）把 4GB 地址空间固定分成这些大区，我们的 SoC 只能往里面填：

| 区域 | 地址范围 | 用途 | 本项目对应 |
|---|---|---|---|
| **Code** | `0x0000_0000 ~ 0x1FFF_FFFF` | 向量表 + 程序 | ROM Boot（⑧） |
| **SRAM** | `0x2000_0000 ~ 0x3FFF_FFFF` | 数据 / 堆栈 | 片内 SRAM（⑦） |
| **Peripheral** | `0x4000_0000 ~ 0x5FFF_FFFF` | 外设寄存器 | FIR / DMA / UART 等 |
| External RAM | `0x6000_0000 ~ 0x9FFF_FFFF` | 片外 RAM（预留） | 不用 |
| External device | `0xA000_0000 ~ 0xDFFF_FFFF` | 片外设备（预留） | 不用 |
| **System** | `0xE000_0000 ~ 0xFFFF_FFFF` | NVIC / SysTick 等 | M0 核内置 |

> 关键点：CPU 复位后从 **0x0 读初始栈指针、0x4 读复位入口**，所以 Code 区一定在 0x0；
> NVIC 在 0xE000_E000，是核自带的，不占我们的外设区。

## 3. 完整地址映射表（SoC 顶层）

### 3.1 存储区（Code + SRAM）

| 基地址 | 大小 | 模块 | 挂在哪条总线 | 主/从 | 状态 |
|---|---|---|---|---|---|
| `0x0000_0000` | 64KB | ROM Boot（向量表 + 启动代码） | AHB →(核内置桥)→ AXI | Slave | ⬜ 规范（当前用 RAM 模型代替真 ROM） |
| `0x2000_0000` | 64KB | 片内 SRAM（数据/堆栈） | AXI | Slave | ⬜ 规范（当前 09 把程序+数据都塞进 0x0 的 RAM） |

> **与现有工程的差异说明**：实验 09（`soc_cm0_top.v`）为了先跑通，把 RAM 直接放在 0x0，
> 程序、数据、栈共用 64KB（`RAM_BASE = 0x0000_0000`）。规范做法是"ROM 放 0x0、SRAM 放 0x2000_0000"
> 分开，这样 Code 和 SRAM 才真正各归各的区。**这是下一步要把 09 对齐规范的一处改动。**

### 3.2 外设区（0x4000_0000 起，按"快/慢"分组）

| 基地址 | 大小 | 模块 | 挂在哪条总线 | 主/从 | 状态 |
|---|---|---|---|---|---|
| `0x4000_0000` | 4KB | ⑤ 81 阶 FIR 滤波器 | AXI | Slave | ✅ 已实现 |
| `0x4000_1000` | 4KB | ⑥ DMA 控制器（寄存器口） | AXI | **Master + Slave** | ✅ 已实现（`rtl/dma.v`） |
| `0x4000_2000` | 64KB | ④ AXI→APB 桥（整块 APB 区） | AXI→APB | Slave（桥） | ⬜ 规范（当前 UART 直接挂 AXI 简化了） |
| `0x4001_0000` | 192KB | （预留高速 AXI 扩展） | AXI | — | ⬜ 预留 |

### 3.3 APB 区（在 AXI→APB 桥之后，桥基址 0x4000_2000 内细分）

APB 从设备地址 = `0x4000_2000 + APB偏移`，每个 4KB：

| APB 偏移 | 大小 | 模块 | 状态 |
|---|---|---|---|
| `0x0000` | 4KB | ⑨ UART | ⬜ 规范（当前直接挂 AXI @0x4000_1000） |
| `0x1000` | 4KB | GPIO（预留） | ⬜ 预留 |
| `0x2000` | 4KB | Timer（预留） | ⬜ 预留 |
| `0x3000` | 4KB | SPI/I2C（预留） | ⬜ 预留 |

> 分组逻辑：FIR、DMA 是**高频、宽数据**的，直接挂 AXI，编号靠前；UART/GPIO/Timer 是
> **慢速、窄**的，统一挂到 AXI→APB 桥后面，桥只占一个 AXI 从设备位，APB 内部再细分。
> 这样 AXI 从设备数量少、译码简单，慢外设也不拖累高速总线。

## 4. 每个外设内部的寄存器偏移（结合现有工程）

> 下面"偏移"是相对该外设基地址的；绝对值 = 基地址 + 偏移。✅ 表示现有 RTL 已实现。

### 4.1 FIR 滤波器（基址 `0x4000_0000`，✅ 来自 `rtl/fir_axi.v`）

| 偏移 | 寄存器名 | 访问 | 说明 |
|---|---|---|---|
| `0x000` | CTRL | W | bit0=1 清空延迟线（flush） |
| `0x004` | DIN | W | 写一个样本（16bit，Q1.15） |
| `0x008` | DOUT | R | 读一个滤波结果（16bit） |
| `0x00C` | STATUS | R | `fifo_count / fifo_full / fifo_empty` |
| `0x100 + 4·k` | COEF[k] | W | 第 k 个系数（k=0..NTAP-1），81 阶占 0x100~0x244 |

### 4.2 DMA 控制器（基址 `0x4000_1000`，✅ 来自 `rtl/dma.v`）

每通道 0x10 字节，通道 N 的寄存器在 `0x10·N + 偏移`：

| 偏移 | 寄存器名 | 访问 | 说明 |
|---|---|---|---|
| `0x00` | SRC | W | 源地址（字节） |
| `0x04` | DST | W | 目的地址（字节） |
| `0x08` | LEN | W | 传输字数（32bit 字个数） |
| `0x0C` | CTRL | W/R | bit0 START，bit1 SRC_INC，bit2 DST_INC，bit31 DONE |

### 4.3 UART（基址 `0x4000_2000`（规范）/ `0x4000_1000`（当前），✅ 来自 `rtl/uart_axi.v`）

| 偏移 | 寄存器名 | 访问 | 说明 |
|---|---|---|---|
| `0x000` | DATA | W | 写一个字节到发送 FIFO |
| `0x004` | STATUS | R | bit0 = tx_busy（忙标志） |

## 5. 中断向量分配（DMA / FIR / UART）

### 5.1 Cortex-M0 的异常号约定（先认清哪些是系统保留的）

| 异常号 | 含义 |
|---|---|
| 0 | （初始栈指针值，不是异常） |
| 1 | Reset |
| 2 | NMI |
| 3 | HardFault |
| 4~10 | 保留 |
| 11 | SVCall |
| 12~13 | 保留 |
| 14 | PendSV |
| 15 | SysTick |
| **16~47** | **外部中断 IRQ0~IRQ31（最多 32 个，这里才归我们用）** |

### 5.2 我们的分配（IRQ 号 = 异常号 - 16）

| 异常号 | IRQ | 中断源 | 优先级 | 说明 |
|---|---|---|---|---|
| 16 | IRQ0 | FIR 滤波完成 | **最高** | 数据到了要及时读走 FIFO |
| 17 | IRQ1 | FIR 错误（溢出/读空） | 高 | 完成在前、错误在后 |
| 18 | IRQ2 | DMA 通道 0 完成 | 中 | ↓ 同模块连续 |
| 19 | IRQ3 | DMA 通道 1 完成 | 中 | |
| 20 | IRQ4 | DMA 通道 2 完成 | 中 | |
| 21 | IRQ5 | DMA 通道 3 完成 | 中 | |
| 22 | IRQ6 | DMA 通道 4 完成 | 中 | |
| 23 | IRQ7 | DMA 通道 5 完成 | 中 | ↑ 同模块连续 |
| 24 | IRQ8 | DMA 全局错误 | 中 | 完成在前、错误在后 |
| 25~26 | IRQ9~10 | （预留空档） | — | 留空 |
| 27 | IRQ11 | UART 接收完成 RX | 低 | |
| 28 | IRQ12 | UART 发送完成 TX | 低 | |
| 29~47 | IRQ13~31 | （预留空档） | — | 留空 |

### 5.3 这样排的理由

- **完成优先于错误**：FIR done=16 < FIR error=17；DMA done=18~23 < DMA error=24。
- **同模块连续**：DMA 6 个通道完成号 18~23 连成一片，软件里好按 `IRQ2+ch` 算。
- **留空档**：25/26、29~47 留着，以后加 GPIO/Timer 不至于重排。
- **按优先级**：FIR 是数据实时性的关键（最高），DMA 次之，UART 最慢（最低）。
- 只用了 32 个外部中断里的 13 个，**留了 19 个空位**，完全满足 ARMv6-M 上限。

> **现状**：现有工程的 M0 `IRQ/NMI` 输入目前都接地（没接中断线），所以这张表是**规范**。
> 下一步做软硬协同时，把 `fir_axi` 的"完成脉冲"、`dma.v` 的 `irq` 接到 M0 的 NVIC 输入，
> 就按这张表的号接。
