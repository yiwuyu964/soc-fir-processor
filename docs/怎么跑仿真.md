# 怎么自己跑仿真（一步步照做）

> 文档信息 ｜ 类别：参考与手册类 ｜ 所属：跨阶段 ｜ 状态：在用 ｜ 索引：`docs/README.md §1.5`
> 适用：阶段 0~6 全部交付物。所有命令都在仓库根目录（`工作区\`）执行。

## 第一件事：先确认你在正确的目录

绝大多数「系统找不到指定的路径。」都是因为当前目录不对。先执行：

```powershell
cd "C:\Users\admin\Desktop\比赛\工作区"
Get-Location          # 必须显示这个路径
Test-Path sim\sim.cmd # 必须显示 True
```

如果懒得确认目录，用绝对路径永远能跑：

```powershell
& "C:\Users\admin\Desktop\比赛\工作区\sim\sim.cmd"
```

> 注意：本手册里的 PowerShell 语法（`$rtl = ...`、`Select-Object`、`Test-Path`）
> 只能在 PowerShell 里跑。在 `cmd.exe` 里敲会报
> 「'Get-ChildItem' 不是内部或外部命令」。

## 0. 前置检查（只需做一次）

三样工具必须在 PATH 里。在 PowerShell 里敲：

```powershell
iverilog -V | Select-Object -First 1
arm-none-eabi-gcc --version | Select-Object -First 1
python --version
```

本机应当显示：

```
Icarus Verilog version 12.0 ...
arm-none-eabi-gcc.exe (Arm GNU Toolchain ...) 14.2.1 ...
Python 3.x.x
```

> 缺 `arm-none-eabi-gcc` 时 `tb_soc` / `tb_phase6` 会失败（编不了固件）；
> 缺 `python` 时固件和 FIR 向量都生成不了。

## 1. 一条命令跑全部（最常用）

```powershell
sim\sim.cmd
```

它会依次做 5 件事，不需要你手动做别的：

| 步骤 | 干什么 |
|---|---|
| ① 全量编译检查 | 把 RTL + 所有测试台一起编译，专抓"重名模块"这类问题 |
| ② 重建主固件 | `python sw/build.py` → `sw/firmware.hex`（被 .gitignore 忽略，必须现编） |
| ③ 生成诊断固件 | `python sim/tinyfw.py` → `sw/probe.hex` |
| ④ 生成 FIR 向量 | `python fir/fir_coeff.py` → 运行目录下的 `fir/*.hex` |
| ⑤ 逐个跑 24 个测试台 | 每个台单独编译 + 单独跑 |

### 成功的样子（最后几行）

```
测试台                   编译 运行 结论
---                    -- -- --
tb_ahb2axi            OK 通过 ===== PASS: 20 项检查全部通过，AXI 协议无违规 =====
...
tb_phase6_fir_dma     OK 通过 ===== PASS: 阶段6 FIR×DMA 端到端通过（误差 0% < 0.1%）=====
tb_uart_echo          OK 通过 ===== PASS: 23 项检查全部通过，UART 回显闭环正常 =====

===== 全部通过：24 个测试台 =====
```

### 失败的样子

```
===== 有 1 个测试台未通过 =====
   tb_xxx : ===== FAIL: N 项失败 =====
```

先看被测的那个测试台名，再去它的 `TB/tb_xxx.v` 里找判据。

## 2. 常用的几种跑法

```powershell
# 只列出有哪些测试台（不跑）
sim\sim.cmd -List

# 只跑名字里含某关键词的（-Only 是正则匹配）
sim\sim.cmd -Only dma          # tb_dma / tb_dma_engine / tb_dma_ic / tb_dma_self
sim\sim.cmd -Only soc          # tb_soc / tb_soc_bus / tb_soc_probe
sim\sim.cmd -Only phase6       # 阶段6 那一个
sim\sim.cmd -Only "fir|uart"   # 支持正则

# 跳过"全量编译检查"（只在你赶时间时用，不建议）
sim\sim.cmd -NoLint

# 保留波形文件（默认会删掉 .vcd 以免污染目录）
sim\sim.cmd -KeepVcd
```

## 3. 只跑一个测试台（不经过 sim 脚本）

当你想改一行看一行、或要接 GTKWave 看波形时用这个：

```powershell
# 1) 抓出所有 RTL 文件
$rtl = Get-ChildItem RTL -Recurse -Filter *.v | ForEach-Object FullName

# 2) 辅助文件：和 sim.ps1 用的是同一套，多带几个没影响
$h = @("TB/axi_protocol_checker.v","TB/axi_id_contract_check.v","TB/axi_mem_model.v") +
     @(Get-ChildItem TB -Filter "phase5_*" -File | ForEach-Object FullName)

# 3) 编译（-s 指定顶层测试台；-I 是 CPU IP 的 include 路径）+ 运行
iverilog -g2012 -Wall -s tb_dma -I RTL/cpu/cortexm0ds -o run.out ($rtl + $h + "TB/tb_dma.v")
vvp run.out
```

>  少带辅助文件会报 `Unknown module type: axi_protocol_checker` 之类的错误。
> **图省事就照上面这样把 3 个 `.v` + 所有 `phase5_*` 全带上**，不会有害。

几个常用的辅助文件（按测试台需要加）：

| 文件 | 什么时候要 |
|---|---|
| `TB/axi_protocol_checker.v` | 几乎所有 AXI 相关测试台 |
| `TB/axi_id_contract_check.v` | 检查 ID 契约（契约C） |
| `TB/axi_mem_model.v` | 桥/DMA 的存储模型 |
| `TB/phase5_*.v` / `.sv` | 阶段5 的覆盖率与 fabric 模型 |

> 跑 `tb_soc` / `tb_phase6_fir_dma` 前必须先编固件：
> ```powershell
> python sw\build.py
> ```

## 4. 固件相关的单独命令

```powershell
# 编固件（产出 firmware.elf / .bin / .hex / .map）
python sw\build.py

# 从黄金模型生成 C 头文件（81 系数 / 337 样本 / 336 期望）
python sw\gen_testvec.py

# 生成 UART 探针用的最小固件（tb_soc_probe 需要）
python sim\tinyfw.py

# 生成 FIR 系数与测试向量（coeffs.hex / stim.hex / exp.hex）
python fir\fir_coeff.py --outdir fir
```

注意：`sw/*.hex`、`sw/*.elf`、`sw/*.bin`、`sw/*.map`、`fir/*.hex` 都不在版本控制里（生成产物）。
`sim.cmd` 每次会自动重建它们，所以平时不用管；只有你单独跑某个台时才需要手动编。

## 6. 想看波形

### 关键前提：不是所有测试台都会 dump 波形

24 个测试台里，14 个会 dump，10 个不会（没有波形文件，不是命令写错了）：

| 会 dump（能看到波形） | 不会 dump（没有波形） |
|---|---|
| tb_ahb2axi, tb_axi_checker, tb_axi_id_check, tb_axi_sram, tb_axi_to_apb, tb_dma, tb_dma_engine, tb_dma_ic, tb_dma_self, tb_fir, tb_fir_core, tb_fir_core_contract, tb_soc, tb_uart_echo, tb_phase6_fir_dma | tb_axi_ic, tb_fifo_arbiter, tb_phase5_ahb, tb_phase5_integration, tb_phase5_sram, tb_soc_bus, tb_soc_probe, tb_sram_offset, tb_uart_apb_edges |

> 想给某个不 dump 的台加波形，在它的 `initial` 里加三行：
> ```verilog
> $dumpfile("tb_xxx.vcd");
> $dumpvars(0, dut);
> ```

### 三步看到波形

```powershell
# 1) 跑并保留波形（不加 -KeepVcd 的话脚本跑完就把 .vcd 删了）
sim\sim.cmd -Only dma -KeepVcd
```

跑完最后会打印一行 波形目录：

```
波形目录: C:\Users\admin\AppData\Local\Temp\socsim_xxxxxxxx\
```

```powershell
# 2) 进那个目录看有哪些 .vcd
dir "C:\Users\admin\AppData\Local\Temp\socsim_xxxxxxxx\*.vcd"
# 3) 用 GTKWave 打开（本机已装在 D:\iverilog\gtkwave\bin，且已在 PATH）
gtkwave "C:\Users\admin\AppData\Local\Temp\socsim_xxxxxxxx\tb_dma.vcd"
```

>  从 `-Only dma -KeepVcd` 实际跑出来的结果（可供核对）：
> ```
> socsim_xxxx\tb_dma.vcd         0.25 MB
> socsim_xxxx\tb_dma_engine.vcd  0.65 MB
> socsim_xxxx\tb_dma_ic.vcd      0.21 MB
> socsim_xxxx\tb_dma_self.vcd    0.18 MB
> ```
> `tb_phase6_fir_dma` 只 dump 顶层总线信号，约 8 MB；想连内部模块一起看，
> 把 `TB/tb_phase6_fir_dma.v` 里 `$dumpvars(1, dut)` 的 `1` 改成 `0`（会到 200 MB+）。

### 不想用 sim 脚本时

```powershell
$rtl = Get-ChildItem RTL -Recurse -Filter *.v | ForEach-Object FullName
iverilog -g2012 -Wall -s tb_dma -I RTL/cpu/cortexm0ds -o run.out ($rtl + "TB/axi_protocol_checker.v" + "TB/axi_id_contract_check.v" + "TB/axi_mem_model.v" + "TB/tb_dma.v")
vvp run.out            # 波形会落在【当前目录】的 tb_dma.vcd
gtkwave tb_dma.vcd
```

> 这种跑法波形就在你眼前（不会进 temp 目录被删）。

## 7. 出问题怎么查

| 现象 | 原因 / 怎么办 |
|---|---|
| `iverilog: command not found` | Icarus 没进 PATH，装到 `D:\iverilog` 后把 `D:\iverilog\bin` 加进 PATH |
| `firmware.hex` 相关报错 / CPU 不启动 | 忘了编固件：`python sw\build.py`（`sim.cmd` 会自动做，单独跑某个台时不会） |
| `$readmemh: Unable to open ...` | 对应 `.hex` 没生成；看是 `sw/`（跑 build.py）还是 `fir/`（跑 fir_coeff.py）还是 `probe.hex`（跑 tinyfw.py） |
| 编译报 `already declared` | 两个 TB 里定义了同名模块 —— `sim.cmd` 的"全量编译检查"就是专门堵这个的，别用 `-NoLint` 掩盖 |
| 测试台报 `TIMEOUT` | 被测逻辑挂住了（多半是握手没完成）；用 `-KeepVcd` 抓波形看最后几拍 |
| `sim.cmd` 直接报路径/权限错误 | 检查 `$env:TEMP` 是否可写（`sim.ps1` 在 TEMP 下建运行目录） |
| `拒绝访问` 删不掉临时目录 | 本机沙箱/权限问题，换个目录或用管理员权限删 |
